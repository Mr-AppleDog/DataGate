# 10 MVP 任务拆分与验收标准

## 1. 实施原则

MVP 指可以在公司生产内网受控上线的最小版本，不是演示原型。任务应按可验证的纵向能力交付，每个里程碑包含代码、迁移、接口、界面、自动化测试、监控和运维说明。

实现顺序必须保证：

1. 身份、密钥、审计等安全底座先于数据源查询；
2. 解析和授权先于执行；
3. 只读查询稳定后才开放导出与变更；
4. 单源灰度和恢复演练完成后才批量接入 300 个数据源。

## 2. 团队建议

最小可行团队建议：

- 产品/项目负责人 1；
- Java 后端 3 至 4；
- Vue 前端 1 至 2；
- 测试/质量 1 至 2；
- DBA/数据库安全专家 1；
- SRE/运维 1；
- 安全评审兼职或专职 1。

单人或纯 AI 也可逐步开发，但评审职责不能由实现者自我替代。生产数据接入、渗透测试和恢复演练必须有人类 DBA、安全和业务负责人签字。

## 3. 里程碑

| 里程碑 | 目标 | 出口条件 |
|---|---|---|
| M0 基线 | 固化 5.6.2 基座与工程规范 | 可重复构建、测试、部署，无上游样例暴露 |
| M1 安全与资产 | 身份、密钥、数据源、元数据、审计 | 凭据不回显，审计不可变，源可安全同步 |
| M2 授权与 MySQL 查询 | 资源授权、审批、只读查询纵向闭环 | MySQL 恶意语料零写入，撤权 60 秒生效 |
| M3 PostgreSQL/Redis | 三引擎 P0 查询能力 | 连接器一致性和安全测试通过 |
| M4 慢查询与告警 | 采集、聚合、通知、治理闭环 | 告警 5 分钟目标与百万日事件压测通过 |
| M5 导出与变更 | 审批导出、DML/DDL/Redis 写工单 | 幂等、复核、审计、失败处理通过 |
| M6 上线加固 | HA、监控、备份恢复、安全验收 | 全部上线门禁通过并完成小流量灰度 |

## 4. M0：项目基线

### M0-01 固定上游版本

- 基于 RuoYi-Vue-Plus v5.6.2；
- 前端使用对应 plus-ui v5.6.2-v2.6.2；
- 锁定后端 commit 8136a01、前端 commit d0d4519；
- Java 17、Spring Boot 3.5.15；
- 保存上游 tag、commit、许可证和本项目修改说明；
- 禁止从 main/master 浮动构建。

验收：全新机器按 README 可构建；版本接口、制品标签和 SBOM 能定位到精确 commit。

### M0-02 清理与关闭不需要的基座能力

- 禁止公开注册和样例账号；
- 关闭或隐藏多租户入口，固定系统租户；
- 删除演示菜单、演示接口和默认密码；
- 生产关闭 Swagger 公共访问、P6Spy SQL 正文和调试端点；
- 检查框架菜单权限、数据权限与新资源权限命名不冲突。
- 核验并修复/禁用 v5.6.2 工作流任务改派的对象级授权风险，覆盖转办、加签、减签、撤回等相邻接口。

验收：未登录和普通用户无法访问管理/调试入口；代码扫描无示例 Secret。

### M0-03 工程模块和质量门禁

- 建立 02 文档定义的模块；
- 统一错误码、traceId、审计上下文和 API 版本；
- 引入迁移工具、格式化、静态检查、单元测试、集成测试；
- CI 生成 SBOM、依赖漏洞和许可证报告；
- 建立测试容器或独立测试实例，绝不指向真实生产库。

## 5. M1：安全底座与数据源资产

### M1-01 本地账号强化

对应 IAM-001 至 IAM-009：

- 管理员创建、首次改密、密码策略、锁定；
- TOTP 绑定、恢复码和高权限强制；
- 会话查看、单个/全部下线、账号停用全局传播；
- 登录安全审计和频率限制。

测试：暴力破解、会话固定、撤销延迟、CSRF、Token 泄露检查。

### M1-02 凭据保险箱

对应 CRED：

- AES-256-GCM 信封加密；
- KEK Provider SPI、只读挂载实现；
- 凭据只写 API、版本、用途和健康检查；
- 双版本轮换、连接池排空；
- 金丝雀 Secret 日志泄漏测试。

验收：任何 GET/异常/日志/trace/前端状态都没有明文；替换元数据库中的密文到另一 credentialId 后解密失败。

### M1-03 数据源管理

对应 RES：

- MySQL、PostgreSQL、Redis 数据源结构化配置；
- 环境、标签、负责人、TLS、状态；
- SSRF 和网络白名单校验；
- 查询、变更、监控账号绑定；
- 连接测试返回分项能力而非底层异常。

### M1-04 元数据同步

- 库/模式/表/列与 Redis 逻辑 DB/前缀资源；
- 定时/手工同步、单源锁、缺失三次标记；
- 资源树搜索按可见权限过滤；
- 元数据版本和同步审计。

### M1-05 审计基础设施

- 统一 AuditEvent；
- outbox 或等价可靠写入；
- 追加写 API、哈希链和每日根；
- 审计查询只读、字段脱敏；
- 保留分区和归档校验命令。

验收：审计写入故障时高风险业务动作失败关闭；篡改记录可检测。

## 6. M2：授权、审批与 MySQL 查询

### M2-01 资源授权引擎

对应 AUTH：

- 资源路径、动作、Allow/Deny、条件和有效期；
- 显式拒绝优先、细粒度优先、默认拒绝；
- 用户/部门/角色/访问组主体；
- 策略发布版本、节点缓存和撤销事件；
- decision explain API 仅管理员可查看。

测试：03 文档决策表、跨部门、到期、环境、并发旧缓存。

### M2-02 权限申请与 WarmFlow

对应 WF：

- 查询权限申请；
- 资源负责人或 DBA 一级审批；
- 申请人不能自批、代理和转交受控；
- 批准生成 Grant，拒绝不生成；
- 撤回、到期、撤销和完整历史。

### M2-03 MySQL 连接器

- 元数据、AST 解析、资源提取；
- 只读语句白名单和危险结构拦截；
- 只读事务、超时、流式结果、取消；
- EXPLAIN；
- 多数据源独立连接池。

### M2-04 查询控制台

- 数据源/库选择、编辑器、执行、取消；
- 结果分页展示、复制受控、截断提示；
- 历史只保存 SQL/指纹与执行元数据，不保存结果；
- 服务端默认 500 行/10 MB、硬上限 5,000 行/50 MB；
- 节点切换后可查询 executionId 状态。

### M2-05 查询审计

- 记录授权版本、审批、全部资源、SQL 指纹、脱敏 SQL、耗时、行/字节、状态；
- 拒绝、取消、超时和解析失败均入审计；
- 审计详情权限与业务数据权限分离。

里程碑验收：从申请到审批、授权、查询、取消、审计形成完整纵向用例；恶意语料没有任何数据库写入。

## 7. M3：PostgreSQL 与 Redis/Tair

### M3-01 PostgreSQL 连接器

- schema/search_path 处理；
- AST 资源提取；
- COPY、DO、副作用函数、锁语句等拦截；
- read only、statement_timeout、cancel；
- pg_catalog 受控访问和 EXPLAIN。

### M3-02 Redis/Tair 连接器

- RESP 参数解析，不接受原始文本拼接；
- 实例/逻辑 DB/key 前缀/命令类别授权；
- 安全命令白名单；
- SCAN 强制前缀、元素和字节上限；
- 集群 MOVED/ASK 的受控处理；
- 禁止脚本、阻塞、管理和写命令。

### M3-03 跨连接器一致性

- 能力枚举和统一错误码；
- 相同的并发、取消、审计和脱敏行为；
- 驱动版本兼容矩阵；
- 数据源熔断和凭据轮换测试。

验收：三引擎安全语料、超限、断连、取消、撤权和节点故障矩阵全部通过。

## 8. M4：慢查询、告警与治理

### M4-01 采集器

- MySQL performance_schema/慢日志/阿里云增强；
- PostgreSQL pg_stat_statements/日志/阿里云增强；
- Redis SLOWLOG；
- 游标、去重、重启/轮转/重置检测；
- 每源健康和权限预检。

### M4-02 标准化与存储

- SQL 归一化、双指纹、parserVersion；
- 原 SQL 加密与敏感字面量清理；
- 原始分区表、分钟/天聚合；
- 100 万事件/日写入与归档。

### M4-03 规则与告警

- 表单化规则、版本；
- 窗口评估、去重、抑制、维护静默；
- 钉钉、邮件、Webhook SPI；
- outbox、签名、重试、死信。

### M4-04 治理工作台

- 发现、认领、处理中、待验证、解决、忽略；
- 指派、期限、评论、关联变更；
- 前后指标、到期重开；
- 安全 EXPLAIN 和规则化建议。

验收：从构造慢 SQL 到告警通知和治理关闭不超过规定时限；原 SQL 和凭据不出现在通知/日志。

## 9. M5：导出与变更

### M5-01 导出审批

- EXPORT 独立权限；
- 资源负责人 → DBA 两级审批；
- 创建和执行前重新鉴权；
- 后台流式导出、CSV 公式注入防护；
- 加密对象、24 小时生命周期、一次性下载；
- 下载、过期、删除审计。

### M5-02 SQL 变更工单

- DML/DDL 版本化文本、影响说明、回滚方案；
- 业务负责人 → DBA 两级审批；
- 专用变更账号、执行窗口、幂等状态；
- 每条语句结果、影响行数、失败和验证；
- 大表/无 WHERE/锁风险标签。

### M5-03 Redis 变更工单

- 支持有限写命令；
- 每个 key 鉴权和影响清单；
- 禁止脚本、事务、管理命令；
- 逐命令结果和审计。

### M5-04 紧急访问

- 双人审批；
- 最长 2 小时；
- 强制 TOTP、理由和事件编号；
- 自动到期、即时通知和事后复盘。

### M5-05 字段权限与动态脱敏

- 敏感等级、字段标签和脱敏规则版本；
- 手机号、身份证、银行卡、邮箱、地址及自定义掩码；
- 结果列来源追踪，覆盖别名、JOIN、SELECT * 和表达式；
- 无法确认来源时按最严格等级处理；
- VIEW_PLAINTEXT 独立授权、到期和二次认证；
- 查询预览、普通结果和导出使用同一服务端脱敏引擎；
- 元数据重新同步不覆盖人工敏感标签。

验收：重复请求只执行一次；审批后 SQL 被改动无法执行；权限撤销或审批过期后任务终止；没有明文权限的用户在查询和导出中均无法得到敏感字段原值。

## 10. M6：上线加固

### M6-01 HA 和发布

- 两节点负载均衡；
- 节点排空、滚动发布和版本兼容；
- PostgreSQL 主备、Valkey/Redis 兼容缓存高可用；
- 灰度连接器和功能开关。

### M6-02 监控和 SLO

- 09 文档全部关键指标、看板和 P1/P2 告警；
- 采集、队列、连接池、审计、归档、备份可观测；
- 建立值班手册和负责人。

### M6-03 备份恢复

- PostgreSQL PITR；
- KEK 双人恢复；
- Valkey/Redis 缓存全丢失恢复；
- 对象归档校验；
- 实测 RPO ≤ 15 分钟、RTO ≤ 1 小时。

### M6-04 性能与稳定性

- 1,000 账号数据；
- 100 在线、50 并发查询；
- 300 数据源配置和元数据规模；
- 100 万慢事件/日；
- 24 小时稳态和故障注入。

### M6-05 安全验收

- 代码审计、依赖扫描、渗透测试；
- 权限绕过、SSRF、IDOR、XSS、CSRF；
- 凭据日志金丝雀；
- 审计篡改验证；
- 高权限 TOTP 和职责分离检查。

## 11. 自动化测试矩阵

| 层次 | 必测内容 |
|---|---|
| 单元 | 策略算法、状态机、指纹、脱敏、错误码、加解密 |
| 组件 | 每个连接器解析和执行、通知通道、对象存储 |
| 集成 | PostgreSQL 元库、Redis、MySQL/PG/Redis 真实测试实例 |
| 契约 | 前后端 OpenAPI、SPI、Webhook 签名和云 API |
| 端到端 | 申请→审批→查询/导出/变更→审计 |
| 安全 | 恶意语法、越权、竞态、Secret 泄漏、Web 攻击 |
| 性能 | 并发、超大结果、百万事件、队列和连接池 |
| 混沌 | 节点退出、网络断开、Redis 丢失、主备切换 |
| 恢复 | PITR、KEK、归档完整性、回滚 |

测试报告必须保存版本、数据规模、环境和失败证据。禁止用 mock 连接器替代全部生产前集成测试。

## 12. Definition of Done

每项需求只有同时满足以下条件才算完成：

- 代码合并且遵守模块边界；
- 数据库迁移可重复执行；
- 菜单、按钮和服务端权限一致；
- 正常、异常、越权和并发路径有自动化测试；
- 审计事件和监控指标已验证；
- 错误码和 API 文档更新；
- 不记录凭据和结果正文；
- 运维、回滚和兼容说明更新；
- 产品、测试、DBA/安全中的适当角色验收；
- 没有未记录的高风险 TODO。

## 13. 发布门禁

### 13.1 禁止上线项

- 凭据可回显、可下载或出现在日志；
- 使用 SQL 正则作为最终授权；
- 未知 SQL/命令被默认放行；
- 普通用户能执行生产写操作；
- 导出无独立权限和审批；
- 权限撤销依赖重启；
- 审计可被业务 API 修改/删除；
- 无 PITR/KEK 恢复演练；
- 单节点部署用于正式生产；
- 使用默认密钥、默认密码、样例管理员；
- 高危依赖漏洞无书面处置。

### 13.2 分阶段开放

1. 开发环境，假数据；
2. 测试环境，只读副本；
3. 单个低敏生产源，DBA/研发小组；
4. 多源、有限普通用户；
5. 敏感字段识别、字段权限和动态脱敏；
6. 公司全员查询；
7. 导出；
8. 变更工单；
9. 后续新引擎。

每阶段至少观察一个完整业务周期，出现 P1 安全事故立即停止扩围。

## 14. 产品级最终验收场景

1. 管理员创建用户，用户首次改密并绑定 TOTP。
2. DBA 添加三个引擎数据源及分用途凭据，用户看不到密码。
3. 同步资源并指定负责人。
4. 用户申请某生产库两张表 SELECT 权限，负责人审批后生效。
5. 用户查询已授权 JOIN 成功；加入第三张未授权表时整体拒绝且目标库零执行。
6. 用户尝试 MySQL OUTFILE、PostgreSQL COPY PROGRAM、Redis EVAL 均被拒绝并审计。
7. 撤销权限，所有节点 60 秒内拒绝新查询。
8. 用户申请导出，经过两级审批，下载一次后 Token 失效，文件 24 小时删除。
9. 用户提交 DML/DDL 工单，SQL 审批后不可篡改并使用专用账号执行。
10. 三种引擎产生慢查询，5 分钟内通知，负责人完成认领和验证。
11. 应用节点故障时新请求切换，目标库无失控查询。
12. 从备份和 KEK 在 1 小时内恢复，审计哈希链验证通过。
13. 普通用户查询和导出敏感字段只得到脱敏值；临时明文权限需二次认证且到期自动回收。

上述 13 个场景全部通过，且《08-安全审计与威胁模型》《09-部署监控备份恢复设计》的上线门禁全部满足，才可定义为全员推广版本可上线。只完成 P0 时仅允许在低敏数据源和受控人员范围试运行。
