# 系统架构与模块详细设计

## 1. 架构目标

系统以 RuoYi-Vue-Plus 5.X `v5.6.2` 为宿主，采用模块化单体架构起步，在不引入不必要微服务复杂度的情况下保证以下能力：

- 外部数据源和平台元数据库严格隔离。
- 数据源类型通过 Connector SPI 扩展。
- 权限判定、执行、审计和慢查询采集具有清晰边界。
- 应用节点无状态，可运行两个或更多实例。
- 执行器未来可拆成独立服务，但首版仍由 `ruoyi-admin` 统一装配。
- 平台故障不位于业务应用访问数据库的链路中。

## 2. 关键约束

1. 使用 RuoYi-Vue-Plus 5.X，不升级到 6.X，不改用 RuoYi-Cloud-Plus。
2. 使用 Java 17 和 Spring Boot 3.5.15，与上游 `v5.6.2` 保持一致。
3. 公司内部单组织，不向业务用户暴露多租户能力。
4. 框架自带数据权限仅保护平台内部业务数据，不能保护外部数据源。
5. 框架 `dynamic-datasource` 不承担用户管理数据源的查询执行。
6. p6spy 只用于平台元数据库开发诊断，不采集外部数据源 SQL；生产应关闭敏感参数输出。
7. 平台不保存查询结果，不作为数据仓库或缓存数据库。
8. 生产数据源的应用账号不录入平台；平台仅使用专用查询、变更和监控账号。

### 3.1 信任区域

| 区域 | 内容 | 规则 |
|---|---|---|
| 用户区 | 员工浏览器 | 不信任输入；不保存数据库密码和持久查询结果 |
| 接入区 | Nginx/SLB | TLS、请求大小限制、基础限速和安全头 |
| 应用区 | 两个 RuoYi 应用节点 | 无状态；可访问元数据库、Redis 和受管数据源 |
| 密钥区 | Secret 挂载或密钥服务 | 只有凭据服务和执行器服务身份可读取 |
| 数据区 | PostgreSQL、Redis、对象存储 | 与受管业务数据库隔离 |
| 受管数据源区 | MySQL、PostgreSQL、Redis/Tair | 白名单只允许执行/采集节点 |

## 4. RuoYi-Vue-Plus 复用策略

| 上游能力 | 本项目用途 | 限制 |
|---|---|---|
| `ruoyi-system` 用户、部门、岗位 | 员工账号和组织结构 | 不等于外部数据资源权限 |
| Sa-Token | 登录、Token、角色/菜单权限、二次认证 | 数据资源授权由 `ruoyi-db-auth` 完成 |
| WarmFlow / `ruoyi-workflow` | 权限、导出、变更审批流程 | 审批完成后由领域服务生成授权或任务 |
| SnailJob / `ruoyi-job` | 元数据同步、权限过期、慢查询采集、告警重试 | 任务处理必须幂等 |
| Redisson | 缓存、锁、限流、短队列 | 不缓存查询结果 |
| SpringDoc | 项目 API 文档 | 秘密字段不进入示例和响应模型 |
| 框架操作日志 | 普通后台管理操作 | 查询/凭据/审批审计使用独立审计模块 |
| 数据脱敏注解 | 固定 DTO 字段脱敏 | 任意查询结果使用独立列级脱敏引擎 |
| 文件/S3 能力 | 受控导出文件 | 文件加密、水印、过期删除由导出模块扩展 |

### 4.1 新增基础组件选型

| 能力 | P0 选型 | 约束 |
|---|---|---|
| SQL AST | Alibaba Druid SQL Parser | 仅使用 MySQL/PostgreSQL Parser、AST、Visitor；不使用 Druid 连接池，也不把 WallFilter 判定当最终授权 |
| 目标连接池 | HikariCP | 由执行器按数据源、用途、凭据版本建立小池；不得注册到 dynamic-datasource |
| 平台缓存 | Valkey，Redisson 客户端 | 使用 Redis 协议；上线前验证 RuoYi 当前 Redisson 版本的兼容性 |
| 元数据库 | PostgreSQL | 保存配置、授权、状态与审计，不保存查询结果 |
| 文件 | 公司现有 S3 兼容对象存储 | 私有 Bucket、服务端加密、短时一次性下载 |

SQL Parser 采用 Apache-2.0 的 Alibaba Druid，是因为其提供 MySQL、PostgreSQL 的独立 Lexer、Parser、AST 和 Visitor。依赖版本在 M0 结合 Java 17、上游 BOM、CVE 和语料兼容测试后锁定；禁止使用浮动版本。参考：[Alibaba Druid SQL Parser](https://github.com/alibaba/druid/wiki/SQL-Parser)。

### 4.2 多租户处理

- 通过上游提供的配置方式关闭业务多租户隔离，或固定唯一系统租户。
- 不删除上游租户代码，以降低后续合并上游安全修复的成本。
- 不显示租户、租户套餐和租户切换入口。
- 自动化测试必须验证所有平台表不会因错误租户上下文出现空数据或越权。
- 外部数据源资源模型不得复用 `tenant_id` 表达公司、部门或数据库归属。

## 5. Maven 模块结构

```text
ruoyi-modules/
├─ ruoyi-system/                  # 上游
├─ ruoyi-workflow/                # 上游
├─ ruoyi-job/                     # 上游
├─ ruoyi-db-core/                 # 公共领域类型和 Connector SPI
├─ ruoyi-db-resource/             # 数据源、资源目录、凭据和元数据同步
├─ ruoyi-db-auth/                 # 外部数据资源权限和判定
├─ ruoyi-db-workflow/             # 权限/导出/变更领域流程，适配 WarmFlow
├─ ruoyi-db-console/              # 工作台会话、收藏和执行编排
├─ ruoyi-db-executor/             # 查询、Redis、导出、变更执行网关
├─ ruoyi-db-audit/                # 专项不可变审计
├─ ruoyi-db-observability/        # 慢查询采集、指纹、聚合和治理
├─ ruoyi-db-alert/                # 告警规则、事件和通知通道
└─ ruoyi-db-connectors/
   ├─ connector-mysql/
   ├─ connector-postgresql/
   ├─ connector-redis/
   └─ connector-aliyun/
```

首版所有模块由 `ruoyi-admin` 装配为一个部署单元。模块间只能通过公开 Service/SPI 或领域事件调用，禁止跨模块直接注入 Mapper。

## 6. 模块职责

### 6.1 `ruoyi-db-core`

只包含无持久化依赖的公共契约：

- `DataSourceType`、`EnvironmentType`、`ResourceType`、`DbAction`。
- `ConnectorCapability`、`DataSourceConnector`、`MetadataProvider`。
- `QueryParser`、`QueryPlan`、`ExecutionRequest`、`ExecutionResultMeta`。
- `SlowQueryProvider`、`SlowQueryRecord`、`CollectorCursor`。
- 安全值对象，例如不会在 `toString()` 中输出内容的 `SecretValue`。
- 领域事件 DTO，不包含 Mapper、Controller 和数据库实现。

### 6.2 `ruoyi-db-resource`

职责：

- 环境、数据源、资源目录、标签、Owner 和状态。
- 凭据加密、版本、连接验证和轮换。
- 元数据同步任务及资源新增、变更、下线标记。
- 根据数据源类型选择 Connector。

禁止：

- 不执行用户提交的任意查询。
- 不向前端返回密码密文、Nonce 或连接 URL 中的密码。
- 不把受管数据源加入平台 MyBatis `DataSource` 路由。

### 6.3 `ruoyi-db-auth`

职责：

- 资源授权、动作、条件、有效期和显式拒绝。
- 用户、部门/用户组的授权归并。
- 权限判定、解释、缓存和缓存失效。
- 字段可见性和明文权限判定。

输入为规范化资源 ID 和动作，不能直接接受未经校验的资源名称字符串。

### 6.4 `ruoyi-db-workflow`

职责：

- 权限、紧急权限、导出、DML、DDL 工单领域对象。
- 计算应使用的 WarmFlow 流程定义。
- 监听流程完成、拒绝、撤回事件。
- 流程完成后生成不可变审批快照，并调用授权或执行服务。

WarmFlow 负责流程引擎，本模块负责业务合法性；不得只依赖流程图节点限制申请人自审。

### 6.5 `ruoyi-db-console`

职责：

- SQL/Redis 工作台会话。
- 有权元数据树、编辑器补全数据和收藏语句。
- 将请求编排到解析、授权、规则、执行、脱敏和审计链路。
- 展示查询状态，不持久保存查询结果。

### 6.6 `ruoyi-db-executor`

职责：

- 独立连接池注册表和连接生命周期。
- 数据源级、用户级和平台级并发控制。
- 会话参数、只读事务、超时、取消和结果流式读取。
- SQL、Redis、导出和变更的不同执行策略。
- 字段级脱敏前的数据映射，但不持久保存结果。

执行器必须假设所有输入均不可信，即使调用方已经做过权限校验，也要验证签名化执行计划、数据源状态和最终限制。

### 6.7 `ruoyi-db-audit`

职责：

- 查询、授权、审批、导出、变更、凭据和安全配置事件。
- 追加写入、检索、归档、哈希链和报告。
- 提供事件写入接口，不暴露更新/删除业务接口。

### 6.8 `ruoyi-db-observability`

职责：

- 慢查询来源、游标、增量任务和幂等。
- SQL/命令指纹、样例、时间窗口聚合和趋势。
- 治理负责人、状态、评论和验证窗口。
- 向告警模块发布规范化指标事件。

### 6.9 `ruoyi-db-alert`

职责：

- 规则、模板、事件、去重键、静默和抑制。
- 通知路由、通道 Secret 和投递重试。
- 钉钉、邮件、通用 Webhook SPI；扩展飞书和企微。

## 7. Connector SPI

### 7.1 能力声明

每个 Connector 必须声明：

```text
METADATA_CATALOG
READ_QUERY
EXPLAIN
EXPORT
CHANGE_DML
CHANGE_DDL
SLOW_QUERY_PULL
QUERY_CANCEL
COLUMN_LINEAGE
FIELD_MASKING
```

未声明的能力在 UI、API 和执行器三层均不可用。

### 7.2 核心接口

```java
public interface DataSourceConnector {
    DataSourceType type();
    Set<ConnectorCapability> capabilities();
    ConnectionTestResult test(ConnectionProfile profile, SecretValue secret);
    MetadataProvider metadataProvider();
    QueryParser queryParser();
    QueryExecutor queryExecutor();
    Optional<SlowQueryProvider> slowQueryProvider();
}
```

实际代码应遵循 RuoYi-Vue-Plus 5.X 现有包命名和代码风格；上例用于确定职责，不要求逐字复制。

### 7.3 连接配置

`ConnectionProfile` 只含非秘密信息：主机、端口、数据库、参数白名单、TLS 模式和超时。密码、Token、AccessKey Secret 使用 `SecretValue` 单独传递，且其 `toString()` 永远返回固定掩码。

## 8. 查询执行链路

### 8.1 编排顺序

```text
1. Sa-Token 登录与功能权限
2. 数据源/资源可发现性检查
3. 方言解析与资源提取
4. 资源权限判定
5. 环境安全策略判定
6. 生成短期 ExecutionPlan
7. 获取全局/数据源/用户并发许可
8. 解密并选择查询凭据
9. 获取独立连接池连接
10. 设置只读、超时、数据库/Schema
11. 执行并流式读取
12. 列来源映射与脱敏
13. 返回受限结果
14. 写入查询审计
15. 释放连接和并发许可
```

### 8.2 ExecutionPlan

解析和授权后生成不可由客户端构造的内部执行计划，至少包含：

- planId、用户、会话、数据源、数据库和方言。
- 原始 SQL 的 SHA-256、规范化 SQL 和语句类型。
- 引用资源 ID、列来源、授权决策 ID。
- 最大时间、行数、字节数、并发和脱敏级别。
- 创建时间和短期过期时间。
- 服务端签名或只存储在服务端缓存中的计划对象。

执行器拒绝直接接收“数据源 ID + 任意 SQL”形式的内部调用。

### 8.3 连接池隔离

- 每个数据源和凭据用途分别建立小型池，查询池与变更池隔离。
- 连接池按需创建，空闲一定时间后回收，避免 300 个数据源全部保持大量连接。
- 默认查询池最大 5 个连接；数据源可单独配置但受平台总并发限制。
- 凭据轮换导致池版本变化，旧池停止借出并在连接归还后关闭。
- 禁止把数据库密码拼入可记录的 JDBC URL。

## 9. 缓存与一致性

### 9.1 Valkey/Redis 协议缓存

允许缓存：

- 用户功能权限和资源权限决策。
- 数据源非秘密配置和能力声明。
- 有权元数据树的短期结果。
- 短期 ExecutionPlan。
- 分布式并发计数、锁和事件去重键。

禁止缓存：

- 数据库明文密码。
- 查询结果和导出文件内容。
- 未脱敏的 SQL 样例参数。

### 9.2 权限版本

每次用户组成员、授权、资源状态或安全策略变更时增加相关 `policy_version`。缓存键必须包含版本；同时发布失效事件。即使失效事件丢失，新版本键也不会命中旧决策。

## 10. 异步任务

使用 SnailJob 承担：

- 元数据同步。
- 权限到期和临时文件删除。
- 慢查询增量采集和时间窗口聚合。
- 告警计算和通知重试。
- 审计归档与哈希校验。
- 凭据有效性巡检。

每个任务必须有业务幂等键、最大重试次数、退避策略和死信/人工处理入口。

## 11. 前端设计边界

前端基于 plus-ui 配套版本：

- 页面放在 `src/views/db/`。
- API 放在 `src/api/db/`。
- SQL 编辑器采用 Monaco，方言和补全数据由服务端返回。
- 资源树使用后端过滤后的数据，不能在浏览器下载全量资源再隐藏。
- 查询结果只存于当前页面内存；刷新即丢失。
- 密码输入组件永不回填，浏览器禁止自动保存数据库密码字段。
- 长任务通过轮询、SSE 或 WebSocket 获取状态，首版优先复用框架已有能力。
- 所有权限仍以服务端为准，按钮指令只改善体验。

## 12. 扩展与拆分路径

达到以下任一条件时评估将执行器拆为独立服务：

- 持续并发查询超过 100。
- 应用节点频繁因数据库驱动或查询结果内存压力重启。
- 需要将执行节点部署在多个网络区域。
- 需要对执行节点使用更严格的主机权限和密钥访问策略。

拆分前保持 `ruoyi-db-executor` 的公开接口不依赖 Web Controller、RuoYi Mapper 或页面 DTO。

## 13. 架构验收

- 不存在从 Controller 直接获取凭据并执行 SQL 的代码路径。
- 不存在将受管数据源注册进 MyBatis `dynamic-datasource` 的实现。
- 各 Connector 可独立进行契约测试。
- 任一应用节点下线不会丢失登录会话、审批状态或任务游标。
- 权限回收后旧缓存不能继续授权。
- 查询取消后连接池中没有仍运行的语句。
- 日志、异常和 Actuator 信息不暴露连接密码或查询结果。
