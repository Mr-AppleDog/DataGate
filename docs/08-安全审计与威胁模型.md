# 08 安全审计与威胁模型

## 1. 安全目标

平台集中持有大量数据源访问能力，因此其安全等级不得低于生产数据库运维系统。核心目标是：

- 用户不知道目标数据源凭据；
- 每次访问都能准确回答“谁、在何时、因何权限、访问了什么、做了什么、结果规模如何”；
- 普通查询无法写库、越权或绕过审批；
- 凭据、查询结果和敏感 SQL 不进入非必要存储；
- 单节点、单数据源、单通知通道故障不扩大为全平台事故；
- 权限撤销、人员离职和凭据泄露可快速止损并追溯。

## 2. 资产与信任边界

### 2.1 关键资产

1. 目标数据源凭据和云 API 密钥；
2. 用户身份、TOTP 密钥、会话；
3. 授权策略、审批结果、资源负责人关系；
4. SQL、Redis 命令、导出文件和慢 SQL 原文；
5. 审计证据和哈希链；
6. 平台元数据库、Redis、对象存储备份；
7. 应用签名密钥、KEK 和 TLS 私钥。

### 2.2 信任区

- 用户终端区：不可信；
- Web/API 区：处理身份与业务请求；
- 执行器区：可连接目标数据源，最高风险；
- 调度/采集区：持有监控访问能力；
- 元数据区：保存授权、审计和密文；
- 密钥区：KEK 与数据库、代码仓库分离；
- 目标数据区：公司业务数据库；
- 外部通知区：钉钉、邮件、Webhook，不可信输出边界。

生产环境中只有执行器和采集器子网能够访问目标数据库端口。前端、办公终端和普通应用节点不得直连。

## 3. 责任分离

| 角色 | 可以 | 不可以 |
|---|---|---|
| 平台管理员 | 用户、菜单、系统参数、节点管理 | 默认查看业务 SQL 原文和结果 |
| 安全管理员 | 密码策略、密钥轮换、审计策略 | 单独批准自己的生产访问 |
| DBA | 数据源、凭据、变更复核、诊断 | 绕过审计；默认获所有业务表查询权 |
| 资源负责人 | 审批本资源查询/导出 | 审批自己提交的申请 |
| 审计员 | 只读审计、导出审计报告 | 修改权限、执行查询 |
| 普通用户 | 在授权范围查询和申请 | 获取凭据、执行生产写操作 |
| 运维服务账号 | 健康检查、采集 | 交互登录或承担人员身份 |

高权限角色的授予和撤销必须由另一名授权管理员复核。系统至少保留两名应急管理员，但日常不用共享账号。

## 4. 威胁模型

| 威胁 | 典型场景 | 主要控制 |
|---|---|---|
| 身份冒用 | 弱密码、会话窃取、撞库 | 强密码、锁定、TOTP、短会话、设备与 IP 审计 |
| 权限提升 | 越权接口、角色组合过宽 | 服务端 RBAC+资源授权、显式拒绝、职责分离、回归测试 |
| SQL 绕过 | CTE、副作用函数、多语句、编码混淆 | 方言 AST、失败关闭、白名单、安全会话 |
| 凭据泄露 | 日志、接口响应、堆转储、前端 | 信封加密、只写接口、日志脱敏、内存最短驻留 |
| 数据外泄 | 超大查询、导出、浏览器缓存 | 行/字节限制、字段脱敏、审批、短时一次性下载 |
| 审计抵赖 | 管理员删改记录、时钟错误 | 追加写、哈希链、归档、统一时钟、审计员只读 |
| SSRF/横向移动 | 恶意数据源地址访问内网服务 | 地址审批、协议固定、IP/端口白名单、执行区网络 ACL |
| 拒绝服务 | 慢查询、连接耗尽、告警风暴 | 并发配额、超时、队列、熔断、去重抑制 |
| 供应链攻击 | 依赖漏洞、恶意制品 | 锁版本、SBOM、签名制品、漏洞扫描、最小镜像 |
| 内部滥用 | 合法账号批量查看敏感数据 | 最小授权、用途/到期、行为审计、导出审批和告警 |

## 5. 身份与会话安全

### 5.1 本地账号

- 禁止公开注册，账号由管理员创建或批量导入；
- 初始密码一次性，首次登录必须修改；
- 密码至少 12 位，至少包含三类字符，禁止用户名和常见泄漏密码；
- 使用现代自适应哈希算法；若沿用框架算法，部署前验证参数强度并制定升级策略；
- 连续 5 次失败锁定 15 分钟，管理员解锁有审计；
- 重置密码后所有会话和 API Token 立即失效；
- 离职、停用或权限撤销通过事件使所有节点在 60 秒内生效；
- 管理员、DBA、安全管理员、审计员强制启用 TOTP；
- 普通用户访问生产敏感字段、查看慢 SQL 原文或下载导出时支持策略化二次认证。

### 5.2 会话

- 使用 Sa-Token 实现认证，但平台仍需配置服务端会话存储、强制下线和权限版本；
- Cookie 场景启用 Secure、HttpOnly、SameSite，并防 CSRF；
- Token 不写入 URL、日志或 localStorage 长期存储；
- 默认空闲 30 分钟，绝对有效期 8 小时；高权限会话更短；
- 登录成功、失败、TOTP 绑定/解绑、密码修改、会话撤销均写安全审计；
- 本地应急管理员只能在内网固定来源使用，使用即触发通知。

### 5.3 后续统一身份

LDAP/OIDC/钉钉接入通过 IdentityProvider SPI 实现。外部身份的唯一标识不可直接使用可变邮箱；账号绑定、解绑和冲突处理必须人工可审计。

## 6. 凭据与密钥管理

### 6.1 加密方案

- 每个凭据版本生成独立 DEK；
- DEK 使用 KEK 包裹，凭据正文使用 AES-256-GCM；
- AAD 至少绑定 credentialId、sourceId、purpose、version，防止密文搬移；
- 元数据库仅保存 ciphertext、nonce、tag、wrappedDEK、keyVersion；
- KEK 不写数据库、不进 Git、不进镜像，生产通过只读 Secret 挂载或企业密钥服务提供；
- 试用环境允许本地密钥文件，但必须限制权限并明确不可用于生产。

### 6.2 接口

- 创建/更新凭据接口只接收明文一次，响应永不回显；
- 查询接口只返回是否已配置、版本、轮换时间和健康状态；
- 不提供“显示密码”“导出连接串”或可逆调试接口；
- 错误信息不能返回认证失败的完整用户名、地址或驱动连接串；
- 浏览器提交凭据后立即清理表单状态。

### 6.3 轮换

- P0 手工轮换并支持双版本平滑切换；
- KEK 轮换与数据库账号密码轮换分别执行；
- KEK 轮换采用重包裹 DEK，不解密并重写全部业务明文；
- 轮换有审批、双人复核、失败回退和演练记录；
- 疑似泄露时立即停用凭据版本、断开连接池、暂停数据源并通知安全负责人。

## 7. 数据源接入与 SSRF 防护

添加或修改目标地址是高风险管理操作：

- 只支持明确驱动协议，用户不能提交任意 JDBC URL 参数；
- host、port、database、TLS 等以结构化字段保存，连接串由服务端构造；
- 禁止 file、http、ldap、rmi 等非数据库协议；
- 地址必须属于配置的公司网段或审批白名单；
- 拒绝回环、链路本地、云元数据地址和执行器管理网段；
- DNS 名保存解析结果并在连接前复核，防 DNS rebinding；
- 禁止前端自定义驱动类、JAR、证书路径和 socketFactory；
- TLS 默认开启并校验证书；临时例外必须有到期时间和风险批准；
- 数据源新增、地址变化、TLS 关闭、凭据变化都写高风险审计并通知 DBA。

网络层还必须以防火墙/安全组做目的地址和端口白名单，不能只依赖应用校验。

## 8. 应用与接口安全

- 所有接口按菜单权限和资源权限双重校验；
- 资源 ID 必须重新查询归属，禁止仅相信请求中的 sourceId；
- 防止 IDOR：审批、导出、查询历史、告警详情均校验用户可见范围；
- 请求 DTO 使用白名单字段和长度限制，拒绝未知敏感字段；
- 富文本、SQL、错误信息在前端按纯文本展示，防存储型 XSS；
- 附件类型、大小、内容签名和存储路径均校验；
- 幂等键绑定用户、动作和请求摘要，不能被另一用户复用；
- 管理 API 采用更严格频率限制和 TOTP；
- OpenAPI 文档在生产只对管理员开放；
- 禁止在生产开启调试端点、SQL 日志明文、Actuator 敏感端点和 P6Spy 全量输出。

### 8.1 RuoYi 5.6.2 工作流已知风险核验

公开报告指出 v5.6.2 的工作流任务改派接口可能缺少功能权限与任务归属检查。由于本项目的权限、导出和变更均依赖审批，M0 必须对精确 tag 做源码核验：

- 普通用户无权调用任务改派、转办、加签、减签、撤回等管理端点；
- 服务层逐个校验任务归属、当前处理人和管理员权限，不能只依赖 Controller 注解；
- 禁止批量 ID 中混入无权任务形成部分越权；
- 改派前后写入专项审批审计；
- 建立两个低权限账号劫持任意 taskId 的回归用例；
- 未修复前从路由和菜单同时禁用相关能力。

参考：[RuoYi-Vue-Plus Issue #44](https://github.com/dromara/RuoYi-Vue-Plus/issues/44)。Issue 状态不替代本项目独立验证。

## 9. 审计设计

### 9.1 审计范围

| 类别 | 事件 |
|---|---|
| 身份 | 登录、失败、退出、锁定、解锁、改密、TOTP、会话撤销 |
| 管理 | 用户、角色、菜单、参数、通知通道、节点配置 |
| 数据源 | 新增、修改、测试、启停、同步、凭据轮换 |
| 权限 | 申请、审批、授权、拒绝、撤销、到期、策略发布 |
| 查询 | 提交、拒绝、执行、取消、超时、资源、结果规模 |
| 导出/变更 | 全状态、审批、下载、执行步骤、验证 |
| 慢 SQL | 查看原文、认领、忽略、验证、规则和静默变化 |
| 安全 | 越权尝试、危险语句、频率限制、签名失败、密钥事件 |

### 9.2 统一审计事件

必备字段：

- eventId、occurredAt、receivedAt、traceId；
- actorType、actorId、actorNameSnapshot、sessionId；
- clientIp、userAgent、nodeId；
- eventType、action、resourceType、resourceId、resourcePathSnapshot；
- decision、reasonCode、policyVersion、approvalId；
- requestHash、beforeHash、afterHash；
- SQL 指纹、脱敏摘要、语句类别、引用资源；
- status、errorCode、durationMs、rows、bytes；
- previousEventHash、eventHash、archiveBatchId。

审计不保存查询结果。管理对象变化保存经过敏感字段剔除的前后快照哈希和必要差异。

### 9.3 防篡改

- 业务 API 只能追加审计，不提供 update/delete；
- 事件按分片或时间桶形成 previousHash → eventHash 链；
- 每日生成批次根哈希并由独立密钥签名；
- 到期事件先导出只读归档、校验数量和根哈希，再按保留策略清理在线分区；
- 审计员可验证任意归档包完整性；
- 数据库超级管理员仍可能绕过应用，因此生产数据库审计、备份权限和平台管理员职责必须分离。

## 10. 保留与隐私

- 一般查询与管理审计：1 年；
- 权限、导出、DDL、DML 审计：3 年；
- 不同类别写入可独立分区，按最长适用规则保留；
- 审计原 SQL 是敏感数据，查看行为本身再次审计；
- 用户姓名变更不覆盖 actorNameSnapshot；
- 合规删除不能破坏审计责任链；如需匿名化，应保留不可逆主体标识和审批证据；
- 备份、归档和搜索索引的保留期必须与主数据一致。

## 11. 日志与可观测性脱敏

禁止进入日志、指标标签和追踪属性的内容：

- 密码、密文、DEK/KEK、Token、Cookie、TOTP Secret；
- 完整 JDBC URL；
- 查询结果、Redis value、导出文件内容；
- 原 SQL 中的字面量；
- Webhook/SMTP 密钥和完整响应正文。

允许记录：

- sourceId、executionId、fingerprint、动作类型；
- 稳定错误码、耗时、行数、字节数；
- 脱敏后的资源路径和 traceId。

上线前运行日志扫描测试，构造带唯一金丝雀 Secret 的失败流程，确认所有日志和监控系统均无该值。

## 12. 供应链与主机安全

- 使用固定 Maven/npm 版本和锁文件；
- 构建生成 SBOM，扫描高危 CVE 和许可证；
- 制品在 CI 构建、签名，不在生产服务器现场编译；
- 容器使用非 root 用户、只读根文件系统、最小 Linux capabilities；
- 执行器禁止挂载 Docker Socket、宿主机目录和云实例高权限身份；
- 数据库驱动只允许随受信制品发布，禁止后台动态上传；
- 管理端口、JMX、调试端口不得暴露到办公网；
- NTP/时间同步为强依赖，偏差超过阈值告警。

## 13. 安全事件处置

### 13.1 凭据疑似泄露

1. 暂停对应数据源新执行；
2. 强制断开相关连接池；
3. 在目标数据库禁用/轮换账号；
4. 搜索凭据使用和异常查询审计；
5. 轮换平台凭据版本，必要时轮换 KEK；
6. 验证业务应用不受影响；
7. 形成事件报告与改进项。

### 13.2 账号被盗

立即停用用户、撤销全部会话与临时授权，检查登录来源、查询、导出、审批和管理操作；高风险数据源进入观察或暂停状态。

### 13.3 审计完整性异常

停止归档清理，冻结受影响分区的写后操作，使用备份和签名根哈希比对，通知安全与审计负责人。

## 14. 上线安全门禁

以下任一不满足不得开放生产数据源：

- KEK 仍在数据库、代码、镜像或普通环境变量中；
- 前端或普通 API 能获得数据源密码；
- SQL 解析失败时仍可透传；
- 未完成权限绕过、SSRF、IDOR、XSS、CSRF 和并发竞态测试；
- 执行器网络可访问非批准目标；
- 审计可被普通管理员修改或删除；
- 查询无服务端超时、行数/字节数/并发限制；
- 权限撤销不能在 60 秒内生效；
- 未完成恢复演练和凭据泄露演练；
- 高权限用户未启用 TOTP。

## 15. 验收测试

- 使用低权限和不同资源授权账号完成横向、纵向越权测试；
- 使用恶意 SQL/Redis 语料证明写操作和文件访问零执行；
- 模拟节点缓存旧策略，验证版本机制拒绝旧授权；
- 检查浏览器网络响应、日志、trace、错误平台和 heap dump，不出现明文凭据；
- 模拟导出 URL 转发，另一账号和过期 URL 无法下载；
- 修改一条审计记录后，链校验必须失败；
- 数据源地址指向云元数据、回环和非白名单端口时必须被阻断；
- 压力下配额生效，不能耗尽平台或目标数据库连接；
- 会话撤销、离职停用和权限到期在承诺时间内生效。
