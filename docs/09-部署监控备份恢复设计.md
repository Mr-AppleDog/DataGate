# 09 部署、监控、备份与恢复设计

## 1. 部署目标

平台提供两种部署形态：

- 试用/开发：单机 Docker Compose，便于快速验证；
- 生产：至少 2 个无状态应用节点，经负载均衡接入，平台 PostgreSQL 与 Redis 独立部署。

平台仅供公司内网或 VPN 访问。目标数据库只允许来自执行器网络的访问。平台故障不能进入业务应用数据库调用链，因此不会阻塞业务应用自身读写。

生产目标：

- 元数据 RPO ≤ 15 分钟；
- 核心服务 RTO ≤ 1 小时；
- 单应用节点故障不中断新登录、审批和查询；
- 单数据源故障仅影响该数据源；
- 计划内发布可滚动完成。

## 2. 组件拓扑

### 2.1 试用环境

1. Nginx 或同等反向代理；
2. RuoYi-Vue-Plus 应用单节点；
3. PostgreSQL 元数据库单实例；
4. Valkey 单实例（也可使用经过许可证确认的 Redis 兼容服务）；
5. 本地或 S3 兼容对象存储；
6. 可选 Prometheus、Grafana、日志收集器；
7. 只读 Secret 文件挂载。

试用 Compose 不作为生产高可用方案，不保存公司唯一审计副本。

### 2.2 生产最小拓扑

| 组件 | 最小数量 | 要求 |
|---|---:|---|
| L4/L7 负载均衡 | 2 或托管高可用 | TLS、健康检查、源 IP |
| 应用/执行器节点 | 2 | 无状态、跨故障域、同版本 |
| 调度/采集工作节点 | 2 | SnailJob 集群、单任务锁 |
| PostgreSQL 元数据库 | 主备 | 独立实例、PITR、专用账号 |
| Valkey/Redis 兼容缓存 | 主从/Sentinel 或托管版 | 默认 Valkey；会话、缓存、锁，不持久化唯一事实 |
| 对象存储 | 高可用 | 导出、归档、备份，生命周期与加密 |
| Prometheus/日志平台 | 高可用或公司公共服务 | 不采集敏感正文 |
| 密钥服务/Secret 挂载 | 高可用 | KEK 与应用制品、数据库分离 |

P0 可以把 Web API、执行器、采集器打在同一制品中，通过节点角色开关控制职责。若安全审查要求更强隔离，应拆分执行器部署池，但保持相同 SPI 和 API 契约。

## 3. 网络与端口

### 3.1 访问方向

- 用户/VPN → 负载均衡：仅 HTTPS；
- 负载均衡 → 应用节点：应用端口；
- 应用节点 → PostgreSQL、Redis、对象存储、通知服务；
- 执行器节点 → 已批准目标数据库端口；
- 采集节点 → 已批准目标数据库或阿里云 API；
- 监控系统 → 应用指标端点；
- 所有其他方向默认拒绝。

### 3.2 强制规则

- 目标数据库安全组只放行平台执行/采集子网，不放行办公网；
- 数据源出站采用目的 IP、端口白名单；
- 云元数据地址、回环、链路本地和集群管理网段拒绝；
- PostgreSQL 元数据库不向用户网开放；
- Redis 启用认证和 TLS（能力允许时），禁止公网；
- 管理 SSH/RDP 通过堡垒机并有审计；
- 证书由公司 CA 或受信 CA 签发，禁止长期自签例外。

## 4. 配置与 Secret

配置分三类：

| 类别 | 示例 | 存放 |
|---|---|---|
| 普通配置 | 端口、功能开关、限额 | 配置文件/配置中心 |
| 敏感配置 | 元数据库密码、SMTP 密钥 | Secret 挂载/密钥服务 |
| 根密钥 | 凭据 KEK、归档签名密钥 | 独立 KMS/HSM 或只读受控挂载 |

要求：

- 仓库只提交示例配置，不提交真实 Secret；
- 生产 Secret 不通过命令行参数传递；
- 环境变量不是 KEK 的首选方案，因为容易进入进程环境和诊断信息；
- 所有配置有环境、版本、修改人和变更记录；
- 配置热更新只用于低风险项；密钥、数据库连接和安全策略变更走受控发布；
- 节点启动时校验必需配置，不满足则失败停止，不能使用弱默认值。

## 5. 容量基线与资源预算

设计输入：

- 1,000 用户；
- 100 同时在线；
- 50 并发查询；
- 300 数据源；
- 每日 100 万慢查询原始事件。

### 5.1 初始资源建议

以下为压测前的起始值，不是最终采购承诺：

| 组件 | 单节点起始规格 | 数量 |
|---|---|---:|
| 应用/执行器 | 8 vCPU、16 GB RAM | 2 |
| 调度/采集 | 4 vCPU、8 GB RAM | 2，可与应用合并试运行 |
| PostgreSQL | 8 vCPU、32 GB RAM、SSD | 主备 |
| Redis | 4 vCPU、8 GB RAM | 主从 |

上线前必须用实际 SQL、结果宽度、慢 SQL 写入量和网络延迟压测后修正。

### 5.2 连接预算

目标数据库连接预算不能简单采用 300 × 每池最大连接数。

- 平台总活动查询上限 50；
- 单数据源默认活动上限 10；
- 每用户默认上限 3；
- 空闲数据源连接池可缩至 0 或 1；
- 调度采集每源通常仅需 1 条短连接；
- 全局连接预算、元数据库池和 Redis 池分别监控；
- 对目标源配置最大占用比例，默认不超过其 max_connections 的 5%，且需 DBA 确认。

## 6. Docker 与进程安全

- 生产镜像基于受支持的 JRE 17 最小镜像；
- 非 root 用户运行；
- 根文件系统只读，临时目录使用受限临时卷；
- 删除编译工具、shell 工具和无关包；
- 禁止 privileged、hostNetwork、Docker Socket；
- 配置 CPU、内存、进程数和临时空间上限；
- 优雅停机：先停止接收新查询，再取消或等待活动请求，默认 60 秒；
- 健康检查区分 liveness、readiness 和 startup；
- readiness 在元数据库不可用、密钥未加载或节点排空时返回失败。

## 7. 数据库与 Redis 高可用

### 7.1 平台 PostgreSQL

- 使用流复制/托管主备和自动故障切换；
- 开启 WAL 归档与 PITR；
- 应用账号、迁移账号、备份账号、监控账号分离；
- schema 迁移仅由发布流程执行；
- 慢查询原始表与审计表分区；
- 定期 VACUUM、ANALYZE 和索引膨胀检查；
- 主备切换至少每半年演练一次。

### 7.2 Valkey/Redis 兼容缓存

- 默认选择 BSD-3-Clause 的 Valkey；如采用 Redis，必须锁定版本并完成许可证确认；
- 该组件用于会话、缓存、分布式锁和短期调度状态，不是授权或审计的唯一事实源；
- 缓存全丢失后系统应能从 PostgreSQL 恢复权限版本并要求用户重新登录；
- 锁必须有租约、续约和 owner token，防误释放；
- 生产采用主从/Sentinel、Cluster 或托管高可用；
- 禁止在缓存值中保存数据源明文凭据和查询结果正文。

## 8. 对象存储

用途：

- 短期导出文件；
- 审计归档；
- 备份制品；
- 可选报表。

控制：

- Bucket 私有，服务端加密；
- 导出与审计归档使用不同前缀、密钥和权限；
- 应用只能写入随机对象键，不使用用户文件名作为路径；
- 临时下载 URL 最多 5 分钟、一次性语义由平台 Token 补充；
- 导出默认 24 小时删除；
- 归档启用对象锁或等效不可变能力时，保留期需经过合规确认；
- 生命周期删除有可观测记录和失败告警。

## 9. 可观测性

### 9.1 服务指标

- HTTP QPS、错误率、p50/p95/p99；
- 登录成功/失败/锁定；
- 在线会话和各角色数量；
- 执行队列长度、活动查询、取消、超时；
- 每用户/每源并发拒绝数；
- JDBC 池活动、空闲、等待、创建失败；
- 权限判定延迟、缓存命中率、策略版本滞后；
- 审批积压和超时；
- 导出队列、文件大小和失败率；
- 审计写入/归档延迟；
- JVM heap、GC、线程、文件描述符、CPU、磁盘和网络。

### 9.2 慢 SQL 模块指标

按《07-慢查询采集分析与告警设计》暴露采集延迟、吞吐、积压、聚合和通知指标。

### 9.3 SLI 与初始 SLO

| SLI | 初始 SLO |
|---|---|
| 登录和管理 API 月可用性 | ≥ 99.9% |
| 查询提交 API 月可用性 | ≥ 99.5%，不含目标源故障 |
| 权限判定 p95 | ≤ 100 ms |
| 普通管理 API p95 | ≤ 500 ms |
| 慢查询告警延迟 | 95% ≤ 5 分钟 |
| 审计完整写入率 | 100%，失败时业务动作失败关闭 |

查询本身耗时由目标数据源决定，不纳入平台 API 延迟，但排队与执行阶段必须分别记录。

## 10. 平台告警

P1 紧急：

- 审计写入失败或哈希链断裂；
- KEK/签名密钥加载失败；
- 元数据库主库不可用；
- 生产权限版本传播超过 60 秒；
- 执行器网络出现非白名单访问尝试。

P2 重要：

- 查询队列持续超过 80%；
- 连接池等待、超时率、错误率激增；
- 慢查询采集延迟超过 3 个周期；
- 通知 outbox 大量积压；
- 磁盘、WAL、对象存储容量或证书即将到期；
- 备份或校验失败。

平台自身告警与业务慢 SQL 告警应使用不同规则和至少两个独立通知通道。

## 11. 日志与追踪

- JSON 结构化日志，包含 timestamp、level、service、nodeId、traceId、eventCode；
- 用户身份使用内部 ID，不把手机号邮箱作为指标标签；
- SQL 只记录 fingerprint 和脱敏摘要；
- 追踪跨 API、审批、队列、执行器和通知，但不注入结果内容；
- 生产日志默认 INFO，临时提高日志等级必须限时并审计；
- 日志写入失败不能绕过审计，审计是独立可靠链路；
- 日志平台设置与审计不同的访问权限和保留期。

## 12. 备份策略

### 12.1 PostgreSQL

- 持续 WAL 归档，满足 15 分钟 RPO；
- 每日全量或存储快照；
- 备份加密并复制到独立故障域；
- 每次备份记录行数/大小/时间并自动校验；
- 至少每季度做一次指定时间点恢复演练。

### 12.2 Redis

Redis 可做常规快照以缩短恢复时间，但恢复目标允许丢失缓存与会话；不可把 Redis 备份视作授权和审计备份。

### 12.3 对象存储与配置

- 审计归档按不可变策略跨故障域保存；
- 导出文件不做长期备份；
- 备份部署清单、非敏感配置、加密 Secret 包和恢复所需 keyVersion 元数据；
- KEK 备份由安全团队独立保管并采用双人恢复；
- 没有 KEK 的数据库备份不可恢复凭据，必须纳入演练。

## 13. 恢复流程

### 13.1 元数据库灾难恢复

1. 宣布事故并冻结发布和高风险操作；
2. 创建隔离恢复环境；
3. 恢复最近全量备份；
4. 回放 WAL 到目标时间点；
5. 校验 schema 版本、审计根哈希、授权记录数和凭据密文；
6. 加载正确 keyVersion 的 KEK 并抽样做连接测试；
7. 重建 Redis 缓存，强制现有用户重新登录；
8. 先恢复管理与审计只读，再恢复查询，最后恢复导出/变更；
9. 对外宣布恢复并形成报告。

目标是事故确认后 1 小时内恢复核心服务。每次演练必须记录实际 RPO/RTO。

### 13.2 应用节点故障

负载均衡摘除失败节点；运行中查询由取消租约和目标数据库超时兜底。客户端可使用相同 clientExecutionId 查询最终状态，不得盲目重复执行。

### 13.3 Valkey/Redis 缓存全丢失

切换/恢复缓存，递增全局会话纪元使全部登录失效，从 PostgreSQL 重载策略版本和基础缓存；检查调度锁过期后再恢复任务。

## 14. 发布、迁移与回滚

### 14.1 发布步骤

1. CI 完成单元、集成、安全、兼容和迁移测试；
2. 生成版本化镜像、SBOM 和签名；
3. 备份元数据库并确认最近恢复演练有效；
4. 执行向后兼容的 schema expand；
5. 灰度一个非执行节点；
6. 灰度执行器并观察错误率、队列和目标连接；
7. 滚动全部节点；
8. 需要时执行数据回填；
9. 稳定至少一个发布观察窗后再 contract。

### 14.2 数据库迁移

- 采用 Flyway 或项目统一迁移工具，版本文件不可修改已发布内容；
- 大表加列、索引和回填需在线方案；
- 不允许应用启动时由多个节点竞态执行迁移；
- 迁移失败时停止新版本，不自动破坏性回滚；
- 回滚应用版本前确认其兼容当前 schema。

### 14.3 功能开关

连接器、导出、变更和新解析器版本都应支持按环境/数据源灰度。安全规则不得通过普通功能开关永久关闭。

## 15. 运维手册

### 15.1 查询无法取消

确认 executionId 和目标会话 → 使用受控取消账号终止 → 隔离连接池 → 检查驱动 → 如仍存在请 DBA 在目标库处置 → 补齐审计和根因。

### 15.2 数据源连接失败激增

暂停新请求或熔断该源 → 检查网络、证书、凭据版本和数据库状态 → 不在群聊发送连接串 → 恢复后低并发探测 → 逐步解除熔断。

### 15.3 审计写入失败

所有需审计的管理、查询、导出和变更动作失败关闭 → 保留只读状态页 → 修复存储 → 验证链连续 → 人工批准恢复。

### 15.4 导出存储泄露

撤销下载 Token → 隔离 Bucket 策略 → 删除仍在生命周期内的临时导出 → 审查下载日志 → 轮换对象存储凭据 → 通知安全负责人。

## 16. 上线检查表

- 生产至少两个应用节点，负载均衡故障转移验证完成；
- 执行器只可连接批准目标，办公终端不能直连数据库；
- PostgreSQL PITR、跨故障域备份和 KEK 恢复演练完成；
- Redis 全丢失恢复流程验证完成；
- 50 并发查询、100 在线、每日 100 万慢事件压测通过；
- 监控看板和平台 P1/P2 告警就绪；
- 证书、Secret、凭据轮换和应急账号检查完成；
- 灰度、回滚、schema 兼容和节点优雅停机演练通过；
- 审计归档与哈希校验可用；
- 试用 Compose 与生产清单明确隔离，生产不使用示例密码或默认密钥。
