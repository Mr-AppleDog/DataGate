# 07 慢查询采集、分析与告警设计

## 1. 目标与边界

本模块提供跨 MySQL、PostgreSQL、Redis/Tair 的慢查询发现、聚合、告警、认领和闭环治理，目标是在异常出现后 5 分钟内发出告警。

P0 不包含：

- 数据库 APM 全量替代；
- 自动改写并执行优化 SQL；
- 自动创建或删除索引；
- 保存查询结果；
- 对所有数据库指标做完整监控。

平台可以给出基于规则的解释和建议，但执行优化动作必须走变更工单。

## 2. 总体数据流

采集源 → 增量游标 → 原始事件标准化 → 指纹与脱敏 → 去重 → 分钟聚合 → 规则评估 → 告警事件 → 通知投递 → 治理工单 → 验证关闭。

采集、聚合、告警和通知均异步执行。任何一个环节失败不能阻塞查询控制台，也不能影响目标数据库应用流量。

## 3. 统一慢查询事件

SlowEvent 至少包含：

| 字段 | 说明 |
|---|---|
| sourceId | 数据源 |
| engineType/engineVersion | 引擎与版本 |
| occurredAt/collectedAt | 数据库事件时间与采集时间 |
| sourceEventId | 上游可用的唯一键 |
| database/schema | 逻辑位置 |
| username/application/client | 可获得时保存，敏感字段脱敏 |
| rawSqlEncrypted | 可选加密原文，仅授权人员可看 |
| normalizedSql | 去常量、脱敏后的模板 |
| fingerprint | 引擎无关哈希与引擎原生 queryId |
| durationMs | 执行耗时 |
| lockWaitMs | 锁等待，可缺失 |
| rowsExamined/rowsReturned/affectedRows | 可获得的行统计 |
| cpuMs/ioBytes/tempBytes | 可选资源指标 |
| sampleRate | 上游采样率 |
| cursorToken | 对应采集游标 |
| ingestQuality | COMPLETE、PARTIAL、ESTIMATED |

缺失值必须为 NULL 并附质量标志，不能用 0 冒充“没有消耗”。

## 4. 采集适配器

### 4.1 通用要求

- 默认每分钟采集一次，可按源配置 1 至 15 分钟；
- 监控账号必须独立于查询和变更账号；
- 每个源保存已提交游标和候选游标；
- 先落原始事件，再提交游标，保证至少一次采集；
- 通过 sourceId + sourceEventId 或稳定复合键去重；
- 数据库时间统一转换为 UTC 保存，界面按用户时区显示；
- 数据库重启、日志轮转、主备切换、游标倒退时可检测并安全重建；
- 采集任务有单源锁，防止集群节点重复拉取；
- 单次批量和回看窗口有上限，避免恢复后冲击目标源。

### 4.2 MySQL

优先级：

1. 阿里云 RDS/PolarDB 慢日志 API，适合云实例；
2. performance_schema.events_statements_summary_by_digest，用于低开销聚合；
3. 慢查询日志文件或表，仅在运维已提供安全采集通道时使用。

注意：

- performance_schema 摘要不是逐次原始事件，应标为 AGGREGATED；
- 轮询摘要时保存计数和总耗时快照，通过差值生成时间桶；
- 慢日志采集要处理 log rotation、时间戳重复和多行 SQL；
- 不要求授予 PROCESS 或文件系统权限给普通查询账号；
- 阿里云 API 密钥独立加密存储，并遵循最小 RAM 权限。

### 4.3 PostgreSQL

优先级：

1. pg_stat_statements 摘要；
2. PostgreSQL 慢日志；
3. 阿里云 RDS PostgreSQL API 增强。

注意：

- pg_stat_statements 以 queryid、dbid、userid 结合平台指纹聚合；
- 保存上次 calls、total_exec_time、rows 等快照并计算差值；
- 发现 stats_reset 或计数回退时重建基线，不产生负指标；
- 日志采集需解析 duration、statement、bind 参数，参数默认不保存；
- 如果扩展未安装，连接检测应明确返回“能力不可用”，而不是把零数据视为健康。

### 4.4 Redis/Tair

- 使用独立监控账号执行 SLOWLOG LEN 和 SLOWLOG GET；
- 以实例启动纪元和 slowlog id 组成游标；
- 检测 id 回退、SLOWLOG RESET 或实例切换；
- 命令参数默认只保留命令名、key 的脱敏摘要和参数个数；
- 禁止保存可能包含密码、Token、身份证、手机号等完整 value；
- Tair 云 API 如能提供更完整指标，可作为增强源，但不得改变统一事件语义。

## 5. 标准化、指纹和敏感信息处理

### 5.1 SQL 标准化

- 去除无语义注释，保留优化器提示的存在性标签；
- 字面量替换为类型占位符；
- IN 列表折叠并保留元素数量区间；
- 规范大小写、空白、标识符引用；
- 对同一引擎版本保持稳定；
- 原 SQL 解析失败时仍可生成保守哈希，但标记 PARSE_FAILED。

平台同时保存：

- portableFingerprint：便于跨实例归并；
- nativeFingerprint：如 MySQL digest、PostgreSQL queryid；
- parserVersion：便于解析器升级后追溯。

解析器升级不得静默覆盖历史指纹；必要时运行可审计的再归一化任务。

### 5.2 敏感信息

- 默认展示 normalizedSql；
- 原 SQL 只有 SLOW_SQL_RAW_VIEW 权限且完成二次认证后可查看；
- 原 SQL 使用单独数据密钥加密，日志和通知永远不发送原文；
- URL 参数、Bearer、密码、Secret、邮箱、手机号等按规则替换；
- Redis 仅保留命令模板，不保存 value；
- 规则误报支持安全管理员配置，但变更必须审计和版本化。

## 6. 存储与容量

设计基线为 300 个数据源、每日 100 万条原始慢查询事件。

### 6.1 分层

| 层 | 内容 | 在线保留 |
|---|---|---|
| Raw | 逐次事件或摘要差值 | 30 天 |
| 5-Minute Bucket | 指纹、源、5 分钟维度聚合 | 180 天 |
| Hourly Bucket | 指纹、源、小时维度聚合 | 24 个月 |
| Daily Bucket | 指纹、源、天维度聚合 | 3 年 |
| Governance | 认领、评论、验证、状态 | 3 年 |
| Archive | 冷存原始审计包 | 按合规策略 |

原始表按 occurred_at 日分区或月分区；高写入索引只保留 source_id、occurred_at、fingerprint 等查询必需项。详细字段可用 JSONB，但核心筛选字段必须为独立列。

### 6.2 聚合指标

- count、errorCount；
- duration min/max/avg/p50/p95/p99；
- totalDuration；
- rowsExamined、rowsReturned、lockWait、tempBytes 的总和与分位数；
- affectedUsers、affectedDatabases；
- firstSeenAt、lastSeenAt；
- 与过去 7 天同一时段基线的倍数变化。

分位数允许使用可合并草图或直方图近似，必须记录算法版本和误差边界。

## 7. 告警规则

### 7.1 规则维度

规则可按环境、标签、数据源、数据库、指纹、引擎和时间窗口匹配。条件支持：

- 单次最大耗时；
- 时间窗内次数；
- p95/p99；
- 总数据库时间；
- 锁等待；
- 扫描行/返回行比；
- 相比历史基线突增；
- 首次出现；
- 采集器失联或连续失败。

P0 使用受控表单生成规则表达式，不允许管理员直接编写脚本。

### 7.2 默认规则

| 严重级别 | 默认条件示例 | 通知目标 |
|---|---|---|
| P1 | 生产单次 ≥ 30 秒，或 5 分钟总耗时 ≥ 300 秒 | DBA、资源负责人 |
| P2 | 生产 p95 ≥ 5 秒且 5 分钟 ≥ 20 次 | 资源负责人 |
| P3 | 首次出现且单次 ≥ 3 秒 | 治理看板，可选通知 |
| COLLECTOR | 生产源连续 3 个周期采集失败 | 平台运维 |

默认值是上线基线，管理员可按环境下调或按数据源覆盖。修改规则必须版本化并写审计。

## 8. 评估、去重和抑制

- 每分钟评估已经完成的时间桶，允许 2 分钟迟到窗口；
- alertDedupKey = ruleId + sourceId + fingerprint + window；
- 同一告警持续触发时更新计数和峰值，不重复轰炸；
- 默认抑制 15 分钟，P1 在指标继续恶化 2 倍时允许升级通知；
- 数据源维护窗口内可静默业务慢 SQL 告警，但不能静默采集器故障和平台安全告警；
- 静默必须有开始、结束、原因、创建人和审批记录；
- 告警规则故障应隔离到单条规则，并通知规则维护人。

## 9. 通知通道

P0 支持：

- 钉钉机器人；
- SMTP 邮件；
- 通用 HTTPS Webhook。

P1 通过同一 NotificationChannel SPI 增加企业微信和飞书。

### 9.1 消息最小内容

- 严重级别、环境和数据源别名；
- 数据库/模式、SQL 指纹和脱敏模板摘要；
- 触发指标、阈值、窗口和趋势；
- 负责人、治理状态；
- 平台详情链接。

严禁包含凭据、连接串、Token、完整原 SQL、Redis value 或查询结果。

### 9.2 投递可靠性

- 使用 outbox 表持久化待发事件；
- 指数退避重试，默认最多 8 次；
- 4xx 配置错误进入 DEAD 并通知管理员，429/5xx 重试；
- 每次投递记录通道、模板版本、响应码、耗时和脱敏响应摘要；
- Webhook 必须 HTTPS，支持签名、时间戳、防重放和目标域名/IP 白名单；
- 通道密钥使用与数据源凭据相同等级的加密托管。

## 10. 治理闭环

状态机为：

DISCOVERED → CLAIMED → IN_PROGRESS → PENDING_VERIFY → RESOLVED

旁路状态：

- IGNORED：必须选择误报、已知可接受、外部限制等原因并填写到期日；
- 重开动作：验证失败或同指纹再次显著恶化时把状态恢复为 DISCOVERED，不新增 REOPENED 持久状态。

规则：

- DISCOVERED 可自动指派资源负责人；
- CLAIMED 必须有负责人和处理期限；
- IN_PROGRESS 可关联变更工单、代码发布或外部工单链接；
- PENDING_VERIFY 至少等待一个完整观察窗口；
- RESOLVED 保存前后指标、验证人和证据；
- IGNORED 到期自动回到 DISCOVERED；
- 所有状态和评论不可覆盖，只追加历史。

## 11. 分析与建议

P0 提供确定性分析：

- 频次高、总耗时高、锁等待高、扫描/返回比高；
- 是否首次出现或突增；
- SQL 涉及表及现有索引摘要；
- 安全 EXPLAIN 结果；
- 常见建议模板，例如减少 SELECT *、检查过滤列索引、避免无界分页。

平台不得声称建议一定正确。对生产执行 EXPLAIN 时必须使用只读账号、严格超时且不得启用 PostgreSQL ANALYZE；需要真实执行的分析必须经审批。

## 12. 采集器可观测性

每个源至少暴露：

- lastSuccessAt、lagSeconds；
- fetched/accepted/duplicate/error 计数；
- cursor；
- batchDuration；
- permissionError、parseError、rateLimitError；
- 上游能力和版本；
- 连续失败次数。

平台级指标至少包括采集成功率、事件吞吐、队列积压、聚合延迟、规则评估延迟和通知成功率。

## 13. 降级与恢复

- 云 API 限流：退避并延长回看窗口；
- 单源失败：仅隔离该源；
- 聚合延迟：保留原始事件，恢复后补算；
- 通知失败：保留 outbox 并在平台展示；
- 元数据库压力高：优先保留采集落盘，暂停非关键再分析；
- 时间大幅漂移：标记质量异常并告警，不直接丢弃；
- 长时间停机恢复时按限速分批回放，防止告警风暴。

## 14. 验收条件

- 正常情况下，符合规则的事件在数据库发生后 5 分钟内形成告警；
- 重复采集不会生成重复原始事件或重复告警；
- 数据库重启、统计重置、日志轮转和集群节点切换后游标可恢复；
- 通知正文不含原 SQL 敏感常量、Redis value 或任何凭据；
- 每日 100 万事件规模下，采集与聚合持续 24 小时无不可控积压；
- 采集器失联能在 3 个周期内告警；
- 治理记录能完整追溯发现、认领、处理、验证和关闭过程；
- 规则修改、静默、忽略和手工关闭均有审计记录。
