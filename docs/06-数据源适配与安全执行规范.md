# 06 数据源适配与安全执行规范

## 1. 目的

本规范定义平台如何代表用户访问目标数据源。任何连接器都必须先经过统一的身份、授权、审批、风险控制、资源限制和审计链路，不能让前端或业务模块直接获得 JDBC、RESP 连接。

适用范围：

- P0：MySQL、PostgreSQL、Redis；
- P1：阿里云 RDS、PolarDB、Tair 的云 API 增强；
- P2：MongoDB、ClickHouse、SQL Server、Oracle、Elasticsearch/OpenSearch。

## 2. 安全执行总原则

1. 平台元数据库与目标业务数据源严格分离。
2. 查询账号、变更账号、监控账号分离，禁止一个高权限账号通用所有场景。
3. 用户永远不能查看、下载或通过接口获得目标数据源密码。
4. 先解析、再授权、后执行；解析失败时默认拒绝，不能降级为直接透传。
5. 权限校验基于 SQL/命令真实引用的全部资源，而不是用户在界面选择的默认库。
6. 生产环境默认只允许只读语句和安全 EXPLAIN。
7. 服务端强制超时、行数、字节数和并发数；前端传入值只能比平台上限更严格。
8. 查询取消、超时、异常、连接断开均需回收连接并写入审计。
9. 禁止把查询结果正文写入应用日志、链路追踪、错误平台或审计表。
10. 任何适配器新版本都必须通过恶意语句语料库和权限绕过回归测试。

## 3. 统一连接器 SPI

连接器由 db-connectors 模块承载，核心接口至少包括：

| 接口 | 职责 |
|---|---|
| Connector | 标识引擎、版本范围、能力集合 |
| ConnectionTester | 连接测试、账号权限预检、TLS 检查 |
| MetadataExplorer | 枚举库、模式、表、列和 Redis DB 等资源 |
| StatementParser | 拆分语句、分类动作、提取资源、发现危险结构 |
| PolicyEnforcer | 将语句资源映射为统一授权动作并给出允许/拒绝理由 |
| QueryExecutor | 参数绑定、超时、流式读取、取消和统计 |
| ExplainExecutor | 生成且执行只读 EXPLAIN |
| ChangeExecutor | 使用独立变更账号执行已审批工单 |
| SlowCollector | 增量采集慢查询与健康状态 |
| ResultMetadataMapper | 统一列名、类型、精度、可空性及来源信息 |

能力必须通过枚举声明，例如 QUERY、EXPLAIN、EXPORT、CHANGE、METADATA_SYNC、SLOW_COLLECT。业务层不得用数据库类型硬编码分支判断能力。

## 4. 统一执行流水线

一次查询按以下顺序执行：

1. 接收 clientExecutionId、数据源、默认库/模式、SQL 或 Redis 命令、客户端限制。
2. 校验登录态、账号状态、TOTP/二次认证要求和功能菜单权限。
3. 校验数据源状态、环境、维护窗口和用户对数据源的可见权限。
4. 规范化输入，拒绝空语句、超长文本、非法编码和超过语句数上限的请求。
5. 使用对应引擎解析器拆分并生成 StatementPlan。
6. 对每个语句提取动作、引用资源、函数、锁、临时对象及风险标签。
7. 根据授权快照逐资源判定；任一资源被拒绝则整个请求拒绝。
8. 根据环境和动作判断是否需要审批、二次确认或专用账号。
9. 取得并解密对应用途的凭据，仅存在于受控进程内存中。
10. 设置会话安全参数，启动只读事务或变更事务。
11. 注册服务端 executionId 和跨节点取消句柄。
12. 执行并以游标/流方式读取，应用字段脱敏、行数和字节数限制。
13. 正常结束、取消或回滚，清理会话状态并归还连接。
14. 写入不可变查询审计、资源清单、命中策略、耗时和结果规模。

语句批次 P0 上限为 20 条；生产查询控制台默认只允许单条，管理员可按环境下调但不能提高平台硬上限。

## 5. SQL 解析与多语句规则

### 5.1 解析器要求

- P0 基线使用 Alibaba Druid 的 MySQL/PostgreSQL 方言 Parser、AST 和 Visitor，仅作为解析组件；禁止用 Druid 连接池替换执行器的 HikariCP 池；
- 必须使用成熟的方言解析器生成 AST；字符串搜索或正则只能用于前置快速拦截，不能作为最终授权依据。
- 解析器版本必须锁定，并保存解析器版本到审计记录。
- 需要识别 CTE、子查询、视图、JOIN、UNION、函数、跨库引用、动态 SQL、注释提示和多语句。
- 对无法解析的新方言、存储过程体、匿名代码块、客户端元命令，默认拒绝。
- 视图访问至少校验视图本身权限；如可可靠获得依赖关系，还需按策略校验底层对象。生产环境推荐仅授予经过审核的安全视图。

### 5.2 动作分类

| 类别 | 例子 | 普通生产查询 |
|---|---|---|
| READ | SELECT、SHOW 安全子集、只读系统视图 | 可授权 |
| EXPLAIN | 不执行原语句的执行计划 | 可授权 |
| EXPORT | 从已授权查询形成文件 | 必须独立授权和审批 |
| DML | INSERT、UPDATE、DELETE、MERGE | 禁止，走变更工单 |
| DDL | CREATE、ALTER、DROP、TRUNCATE | 禁止，走变更工单 |
| ADMIN | GRANT、KILL、SET GLOBAL、VACUUM FULL 等 | 普通用户禁止 |
| CODE | CALL、DO、存储过程/函数执行 | P0 禁止 |
| UNKNOWN | 无法可靠分类 | 拒绝 |

批次中只要包含不同风险类别，就按最高风险处理；生产控制台不支持把 READ 与变更语句混在一次执行中。

## 6. MySQL 安全规范

### 6.1 支持范围

- P0：MySQL 8.0；
- 兼容验证：MySQL 5.7 仅作为过渡，不承诺全部元数据和计划能力；
- RDS MySQL、PolarDB MySQL 使用相同 SQL 适配器，云监控由阿里云增强适配器提供。

### 6.2 普通查询允许项

- SELECT；
- SHOW DATABASES/TABLES/COLUMNS/INDEX/CREATE TABLE 的受控子集，且结果按授权过滤；
- DESCRIBE/EXPLAIN；
- WITH ... SELECT；
- 仅访问获授权的 information_schema 安全视图，默认隐藏 PROCESSLIST、权限和账号信息。

### 6.3 强制拒绝项

- INTO OUTFILE、INTO DUMPFILE、LOAD_FILE；
- LOAD DATA、HANDLER、LOCK TABLES、UNLOCK TABLES；
- SET GLOBAL、SET PERSIST、INSTALL/UNINSTALL PLUGIN；
- CREATE/DROP/ALTER USER、GRANT、REVOKE；
- KILL、SHUTDOWN、RESET MASTER、PURGE BINARY LOGS；
- 调用存储过程、用户自定义函数或无法确认副作用的函数；
- SELECT ... FOR UPDATE、FOR SHARE、LOCK IN SHARE MODE；
- 写入型 CTE、临时表创建和任何 DDL/DML。

### 6.4 会话保护

- 连接后设置只读事务，优先 START TRANSACTION READ ONLY；
- 设置服务端最大执行时间；必要时同时使用 JDBC queryTimeout；
- 固定字符集与时区，禁止客户端任意修改 sql_mode、optimizer_switch 等关键会话参数；
- 查询结束统一 ROLLBACK，清除临时会话状态；
- 若驱动或数据库版本无法保证会话恢复，直接销毁连接而不是归还连接池。

### 6.5 取消

优先使用 JDBC Statement.cancel；若无响应，由受控管理连接按线程 ID 取消当前查询。取消管理账号只能拥有终止查询所需最小权限，并记录操作者、目标线程和原因。

## 7. PostgreSQL 安全规范

### 7.1 支持范围

- P0：PostgreSQL 14 至 17；
- RDS PostgreSQL 使用相同 SQL 适配器，云监控由阿里云增强适配器提供。

### 7.2 普通查询允许项

- SELECT、WITH ... SELECT；
- EXPLAIN，不默认开放 ANALYZE；
- 经过白名单的 pg_catalog、information_schema 只读视图；
- SHOW 安全参数。

### 7.3 强制拒绝项

- COPY TO/FROM 文件或 PROGRAM；
- SELECT INTO、CREATE TABLE AS、REFRESH MATERIALIZED VIEW；
- INSERT、UPDATE、DELETE、MERGE、DDL；
- CALL、DO、执行未知函数、CREATE FUNCTION；
- SET ROLE、SET SESSION AUTHORIZATION、ALTER SYSTEM；
- LISTEN、NOTIFY、LOAD；
- pg_read_file、pg_ls_dir、lo_import、lo_export、dblink、外部程序相关扩展；
- FOR UPDATE、FOR NO KEY UPDATE、FOR SHARE、FOR KEY SHARE；
- VACUUM、REINDEX、CLUSTER 等管理操作。

### 7.4 会话保护

- BEGIN READ ONLY；
- SET LOCAL statement_timeout、lock_timeout、idle_in_transaction_session_timeout；
- search_path 固定为用户获授权的模式并包含 pg_catalog，不能接受未校验的原始 search_path；
- application_name 写入平台 executionId，便于定位与取消；
- 结束时 ROLLBACK 并 RESET ALL；失败时销毁连接。

### 7.5 EXPLAIN

普通用户仅允许不执行原语句的 EXPLAIN。EXPLAIN ANALYZE 会真实执行语句，P0 仅允许 DBA 在非生产或经审批的生产只读语句上使用，并受更严格超时限制。

## 8. Redis/Tair 安全规范

### 8.1 资源与命令授权

资源维度为实例、逻辑 DB、Key 前缀；动作维度至少分为 KEY_DISCOVER、VALUE_READ、TTL_READ、STRUCTURE_READ、WRITE、ADMIN。

Key 前缀必须按字节序列匹配，不能把用户输入直接拼成 glob。集群模式中的逻辑 DB 固定为 0，平台不得展示不存在的 DB 切换能力。

### 8.2 P0 白名单

| 类别 | 命令 |
|---|---|
| 发现 | SCAN，平台强制 MATCH 为授权前缀并限制 COUNT |
| 通用读取 | TYPE、EXISTS、TTL、PTTL |
| String | GET、MGET，MGET 中每个 key 独立校验 |
| Hash | HGET、HMGET、HGETALL、HSCAN、HLEN |
| List | LRANGE、LLEN |
| Set | SMEMBERS、SSCAN、SCARD、SISMEMBER |
| ZSet | ZRANGE、ZREVRANGE、ZRANGEBYSCORE、ZSCAN、ZCARD、ZSCORE |
| Stream | XRANGE、XREVRANGE、XLEN，禁止阻塞读取 |

所有读取都要限制返回元素数和总字节数。大集合必须引导使用 SCAN 类命令，平台可拒绝无界 SMEMBERS、HGETALL 或 LRANGE。

### 8.3 无条件拒绝

- KEYS、MONITOR、CONFIG、DEBUG、SHUTDOWN；
- EVAL、EVALSHA、FUNCTION、SCRIPT；
- FLUSHDB、FLUSHALL、MIGRATE、RESTORE、DUMP；
- MODULE、ACL、COMMAND、CLIENT KILL、CLIENT PAUSE；
- PSUBSCRIBE、SUBSCRIBE、BLPOP、BRPOP、BZPOP*、XREAD BLOCK；
- MULTI/EXEC/WATCH；
- 任意写命令、未知命令和代理私有管理命令。

INFO、SLOWLOG GET 仅监控连接器可使用，普通查询控制台不开放。

### 8.4 变更工单

Redis 写命令 P0 仅支持经过明确适配的 SET、DEL、HSET、HDEL、EXPIRE 等常用命令；每个 key 都要命中工单授权范围。禁止脚本、事务批次和管理命令。执行前展示影响 key 清单，执行后记录逐命令结果。

## 9. 元数据同步

元数据同步使用监控账号或只读查询账号，周期默认 30 分钟，也支持管理员手动触发。

- 新资源默认不可访问；
- 同步未发现的资源先标记 UNKNOWN，连续 3 次确认后标记 DROPPED，不物理删除历史授权引用；
- 表重命名按删除加新增处理，不能自动迁移授权；
- 同步任务记录开始、结束、游标、成功数、失败原因和数据库版本；
- 元数据界面只能显示当前用户有权发现的资源，不能因搜索接口泄露名称。

## 10. 连接池与凭据生命周期

### 10.1 隔离

- 每个数据源、凭据用途和凭据版本形成独立池键；
- 不能在不同租户概念、不同账号或不同安全环境间复用连接；
- 单数据源池默认最大 5 条，按源可配置，总连接数受全局预算控制；
- 空闲 10 分钟回收，失败连接快速驱逐；
- 连接健康检查必须是无副作用轻量语句。

### 10.2 凭据轮换

管理员写入新版本后：

1. 使用新凭据做连接与权限预检；
2. 原子切换 ACTIVE 版本；
3. 新请求只使用新版本；
4. 旧池进入 DRAINING，等待活动请求结束；
5. 到达最长排空时间后关闭旧池；
6. 记录轮换审计，不记录明文。

解密后的字符数组或字节数组应尽快清零；异常对象和线程名禁止包含连接串或密码。

## 11. 结果集处理与脱敏

- JDBC 必须使用游标/流式读取，禁止一次性加载完整结果；
- 交互查询默认上限 500 行或 10 MB，硬上限 5,000 行或 50 MB，以先到者为准；更大数据量必须使用受审批的导出；
- 单元格硬上限 1 MB，超出截断并标记；
- 二进制字段默认不展示，只显示类型、长度和摘要；独立权限下可下载；
- JSON/XML 同样计入字节上限并做安全转义；
- 字段脱敏在服务端流式阶段完成，前端不能接触原值；
- 脱敏规则优先使用明确字段映射；SELECT * 必须展开元数据后逐列应用；
- 无法可靠判断来源的表达式，在生产环境按最高敏感等级处理；
- 结果页不得被浏览器缓存，下载链接短时、一次性且绑定用户。

## 12. 导出安全执行

导出只能引用已成功保存并通过授权复核的查询定义，不能用隐藏参数替换 SQL。

- 创建导出时重新解析、重新鉴权并锁定策略版本；
- 审批通过后执行前再次鉴权，权限被撤销则终止；
- 默认上限 1,000,000 行或 500 MB；
- 文件使用随机对象键和服务端加密，默认保留 24 小时；
- 下载 URL 有效期不超过 5 分钟且只能使用一次；
- 文件名、内容和元数据均需防公式注入，CSV 中以 =、+、-、@ 开头的文本需安全处理；
- 导出审计记录申请人、审批人、查询摘要、数据源、资源、行数、字节数、下载次数和删除时间。

## 13. 变更执行

P0 支持人工提交 SQL 工单并由专用变更账号执行，不做自动 SQL 优化或自动回滚承诺。

执行前：

- 重新解析动作和资源；
- 校验审批链、执行窗口、账号和工单哈希；
- 计算高风险标签：无 WHERE 的 UPDATE/DELETE、大表 DDL、锁表、全表扫描可能性；
- 要求申请人提供影响评估、备份/回滚方案和验证语句；
- SQL 文本变化即使仅注释变化也需要生成新版本，实质变化必须重新审批。

执行中：

- 一个工单一个受控事务或显式步骤；
- 设置锁等待和执行超时；
- 实时记录当前步骤，禁止并发重复执行；
- DDL 是否事务化按引擎判断，界面明确不可回滚风险。

执行后：

- 记录每条语句状态、影响行数、错误码、开始结束时间；
- 执行验证语句；
- 成功、失败和部分成功都写审计并通知相关人。

## 14. 资源限制与公平性

基线容量为 1,000 用户、100 在线、50 并发查询、300 数据源。

- 每用户默认并发 3，每数据源默认并发 10，全平台并发 50；
- 等待队列默认 100，超出返回容量错误；
- 生产查询默认超时 30 秒，硬上限 5 分钟；
- EXPLAIN 默认 15 秒；Redis 单命令默认 5 秒；
- 调度采用用户与数据源双层公平队列，DBA 不可无界抢占；
- 熔断条件：连接错误激增、超时率过高、人工停用或目标源维护；
- 熔断只影响该数据源，不影响平台登录、审批和其他数据源。

## 15. 安全测试语料

每个连接器至少覆盖：

- 注释、大小写、Unicode 空白、空字节和编码混淆；
- 多语句分隔、嵌套注释、字符串中的分号；
- CTE 包装写操作、SELECT 中的副作用函数；
- 跨库/跨模式限定名、同名对象和 search_path 变化；
- 视图、临时对象、系统目录和隐式资源；
- MySQL OUTFILE/LOAD_FILE、PostgreSQL COPY/PROGRAM/DO；
- Redis 多 key 命令、二进制 key、集群重定向和代理私有命令；
- 超大结果、慢客户端、取消竞态、节点切换和凭据轮换；
- 权限刚撤销、审批过期、缓存旧版本和重复执行。

任一无法解释的授权结果都必须失败关闭，并返回稳定错误码与 traceId，不返回底层凭据、主机细节或堆栈。

## 16. 验收条件

- 普通用户不能通过任何支持的 SQL/Redis 语法产生写入或获取服务器文件；
- 访问多个资源的语句会逐一鉴权，任一拒绝则零执行；
- 权限撤销后 60 秒内所有节点生效，新查询无法继续；
- 超时、取消和客户端断连后，目标数据库无遗留活动语句；
- 结果超限能可靠截断且连接内存稳定；
- 凭据轮换不中断已运行查询，新请求只使用新版本；
- 所有执行路径产生完整审计，并且应用日志不含查询结果或凭据。
