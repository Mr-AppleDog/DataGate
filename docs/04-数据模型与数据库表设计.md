# 数据模型与数据库表设计

## 1. 数据库约定

### 1.1 元数据库

- 生产元数据库使用 PostgreSQL。
- 字符集 UTF-8，时间统一保存为带时区时间，接口输出 ISO 8601。
- 业务主键使用 RuoYi-Vue-Plus 现行雪花 ID 方案，Java 类型 `Long`，前端按字符串传递避免精度丢失。
- 表前缀使用 `dbg_`（Database Governance）。
- 公共审计字段与 RuoYi-Vue-Plus 5.X 的 `BaseEntity` 约定保持一致。
- 如上游多租户插件要求，新表保留 `tenant_id`，但固定为系统租户值；`tenant_id` 不参与外部数据源授权。
- 逻辑删除只用于可恢复的配置对象；审计、执行和慢查询事实表禁止逻辑覆盖历史。

### 1.2 公共字段

配置型表通常包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | 雪花 ID，主键 |
| `tenant_id` | varchar(20) | 固定系统租户，按上游规范 |
| `version` | integer | 乐观锁版本 |
| `create_dept` | bigint | 创建部门 |
| `create_by` | bigint | 创建人 |
| `create_time` | timestamptz | 创建时间 |
| `update_by` | bigint | 更新人 |
| `update_time` | timestamptz | 更新时间 |
| `del_flag` | char(1) | 配置对象逻辑删除标志 |

事实型表使用 `created_at`、`occurred_at` 等不可修改时间字段，不强制继承可更新的 `BaseEntity`。

### 1.3 秘密字段

- 秘密密文使用 `bytea`，不得使用可被日志直接打印的普通字符串实体字段。
- Nonce、认证标签和密文的具体组合由加密实现决定；表中保留算法和密钥版本。
- Java Secret 实体禁止 Lombok 自动生成包含秘密的 `toString()`。
- API DTO 中不存在密文、Nonce、认证标签和主密钥版本字段。

## 2. 复用的上游表

以下能力直接复用 RuoYi-Vue-Plus 5.X 表，不复制一套用户系统：

- 用户、部门、岗位、角色、菜单和角色绑定。
- 登录日志、普通操作日志、字典和参数。
- WarmFlow 流程定义、实例、任务和历史。
- SnailJob 任务和调度日志。

本项目表通过用户 ID、部门 ID、流程实例 ID 引用上游数据，但不为上游表添加外键，避免上游升级冲突；领域服务负责引用校验。

## 3. 数据资产与凭据

### 3.1 `dbg_environment`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | bigint | PK |
| `code` | varchar(32) | UK，例如 `prod` |
| `name` | varchar(64) | 环境名称 |
| `risk_level` | varchar(16) | LOW/MEDIUM/HIGH/CRITICAL |
| `default_policy` | jsonb | 查询默认限制 |
| `status` | varchar(16) | ACTIVE/DISABLED |

生产环境必须初始化为 CRITICAL，不能通过普通配置降低其硬安全上限。

### 3.2 `dbg_data_source`

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| `id` | bigint | PK |
| `environment_id` | bigint | 索引 |
| `type` | varchar(32) | MYSQL/POSTGRESQL/REDIS/TAIR 等 |
| `name` | varchar(128) | 同环境内唯一 |
| `host` | varchar(255) | 非秘密 |
| `port` | integer | 1-65535 |
| `default_database` | varchar(128) | 可空 |
| `connection_options` | jsonb | 仅允许白名单参数 |
| `tls_mode` | varchar(16) | DISABLE/PREFER/REQUIRE/VERIFY_CA/FULL |
| `status` | varchar(24) | DRAFT/VERIFYING/ACTIVE/DISABLED/ERROR/ARCHIVED |
| `owner_type` | varchar(16) | USER/DEPT |
| `owner_id` | bigint | Owner ID |
| `policy_version` | bigint | 权限缓存版本 |
| `last_verified_at` | timestamptz | 最近连接验证时间 |
| `last_error_code` | varchar(64) | 不保存秘密或完整异常 |

索引：

- `uk_dbg_ds_env_name(environment_id, name)`。
- `idx_dbg_ds_type_status(type, status)`。
- `idx_dbg_ds_owner(owner_type, owner_id)`。

### 3.3 `dbg_tag` 与 `dbg_data_source_tag`

`dbg_tag`：`id`、`code`、`name`、`color`、公共字段。  
`dbg_data_source_tag`：`data_source_id`、`tag_id`，复合唯一索引。

标签只用于检索和告警路由，不能隐式授予数据权限，除非未来显式实现标签策略。

### 3.4 `dbg_credential`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `data_source_id` | bigint | 索引 |
| `purpose` | varchar(16) | QUERY/CHANGE/MONITOR |
| `username` | varchar(255) | 可在受限管理页显示 |
| `active_version_id` | bigint | 当前版本 |
| `status` | varchar(16) | ACTIVE/DISABLED/INVALID |
| `last_verified_at` | timestamptz | 最近验证 |
| `rotate_due_at` | timestamptz | 计划轮换时间 |

唯一索引：`uk_dbg_cred_ds_purpose(data_source_id, purpose)`。

### 3.5 `dbg_credential_version`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `credential_id` | bigint | 索引 |
| `version_no` | integer | 同凭据递增 |
| `ciphertext` | bytea | 密文 |
| `nonce` | bytea | 随机 Nonce |
| `algorithm` | varchar(32) | `AES-256-GCM` |
| `key_version` | varchar(64) | 外部主密钥版本标识 |
| `secret_fingerprint` | varchar(64) | 不可逆指纹，用于判断是否重复 |
| `status` | varchar(16) | PENDING/ACTIVE/RETIRED/INVALID |
| `verified_at` | timestamptz | 验证时间 |
| `activated_at` | timestamptz | 切换时间 |
| `retired_at` | timestamptz | 退役时间 |
| `created_by` | bigint | 创建人 |
| `created_at` | timestamptz | 创建时间 |

不允许更新密文版本；轮换始终插入新版本。

### 3.6 `dbg_resource`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `data_source_id` | bigint | 索引 |
| `parent_id` | bigint | 根资源为 0 |
| `resource_type` | varchar(32) | DATABASE/SCHEMA/TABLE/VIEW/COLUMN/REDIS_DB/KEY_PREFIX 等 |
| `physical_name` | varchar(512) | 真实名称 |
| `normalized_name` | varchar(512) | 按数据源规则规范化 |
| `canonical_path` | text | 可读路径，唯一 |
| `metadata` | jsonb | 类型、索引、估算行数等非秘密元数据 |
| `status` | varchar(16) | ACTIVE/DISABLED/DROPPED/UNKNOWN |
| `metadata_version` | bigint | 同步版本 |

| `last_seen_at` | timestamptz | 最近发现 |

索引：

- `uk_dbg_resource_path(data_source_id, canonical_path)`。
- `idx_dbg_resource_parent(parent_id, resource_type, status)`。
- `idx_dbg_resource_name(data_source_id, normalized_name)`，可按需要使用 trigram 索引。

### 3.7 `dbg_column_profile`

| 字段 | 类型 | 说明 |
|---|---|---|
| `resource_id` | bigint | PK，必须是 COLUMN |
| `sensitivity_level` | varchar(16) | PUBLIC/INTERNAL/SENSITIVE/RESTRICTED |
| `masking_type` | varchar(32) | PHONE/ID_CARD/BANK_CARD/EMAIL/ADDRESS/CUSTOM/NONE |
| `masking_config` | jsonb | 自定义掩码配置 |
| `classification_source` | varchar(16) | MANUAL/RULE/IMPORT |
| `confirmed_by` | bigint | 人工确认人 |
| `confirmed_at` | timestamptz | 确认时间 |

元数据同步不得覆盖人工确认的敏感标签。

### 3.8 `dbg_metadata_sync_job`

记录 `data_source_id`、`trigger_type`、`cursor`、`metadata_version`、开始/结束时间、状态、发现/更新/下线数量、错误码和任务 ID。错误详情经过秘密遮蔽。

## 4. 访问控制

### 4.1 `dbg_access_group` 与 `dbg_access_group_member`

访问组独立于 RuoYi 功能角色：

- `dbg_access_group`：名称、说明、Owner、状态、公共字段。
- `dbg_access_group_member`：`group_id`、`user_id`、有效期、来源，复合唯一索引。

### 4.2 `dbg_resource_grant`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `effect` | varchar(8) | ALLOW/DENY |
| `subject_type` | varchar(16) | USER/DEPT/GROUP/ROLE |
| `subject_id` | bigint | 主体 ID |
| `resource_id` | bigint | 授权资源；GLOBAL 范围时为 null |
| `scope_type` | varchar(16) | RESOURCE/GLOBAL |
| `inherit_children` | boolean | 是否继承子资源 |
| `conditions` | jsonb | 标准条件结构 |
| `valid_from` | timestamptz | 生效时间 |
| `valid_until` | timestamptz | 截止时间，生产不可为空 |
| `status` | varchar(16) | PENDING/ACTIVE/SUSPENDED/EXPIRED/REVOKED |
| `source_type` | varchar(16) | MANUAL/REQUEST/SYSTEM/EMERGENCY |
| `source_id` | bigint | 工单或来源 ID |
| `reason` | varchar(1000) | 原因 |
| `policy_version` | bigint | 创建时版本 |

索引：

- `idx_dbg_grant_subject(subject_type, subject_id, status, valid_until)`。
- `idx_dbg_grant_resource(resource_id, status)`。
- `idx_dbg_grant_source(source_type, source_id)`。

### 4.3 `dbg_grant_action`

`grant_id`、`action`，复合主键。动作不放在逗号字符串中，便于检索和约束。

### 4.4 `dbg_policy_version`

按 `scope_type`（GLOBAL/DATA_SOURCE/USER/GROUP）、`scope_id` 保存当前递增版本和更新时间。所有会影响判定的操作必须在同一事务中递增对应版本或写入待发布事件。

### 4.5 `dbg_access_request`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `request_no` | varchar(32) | UK，可读编号 |
| `request_type` | varchar(16) | QUERY/EXPORT/DML/DDL/EMERGENCY/UNMASK |
| `applicant_id` | bigint | 申请人 |
| `resource_snapshot` | jsonb | 申请时资源不可变快照 |
| `action_snapshot` | jsonb | 动作和限制 |
| `reason` | text | 用途 |
| `ticket_ref` | varchar(128) | 外部事项/事件号 |
| `requested_from` | timestamptz | 请求开始 |
| `requested_until` | timestamptz | 请求结束 |
| `workflow_instance_id` | bigint/varchar | 按上游类型 |
| `status` | varchar(24) | 状态机 |
| `submitted_at` | timestamptz | 提交时间 |
| `finished_at` | timestamptz | 完成时间 |
| `version` | integer | 乐观锁 |

### 4.6 `dbg_approval_snapshot`

保存工单的流程定义版本、节点、审批人、意见、时间、结果和审批时请求摘要。只追加，不更新历史结论。

## 5. 查询、导出和变更

### 5.1 `dbg_console_session`

保存用户、数据源、数据库/Schema、客户端会话 ID、创建时间、最近活动时间和过期时间。不得保存查询结果。

### 5.2 `dbg_saved_statement`

保存用户、名称、数据源类型、SQL/命令密文或受控文本、指纹、秘密扫描状态和共享范围。默认私有；共享功能属于 P2。

### 5.3 `dbg_query_execution`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `execution_no` | varchar(36) | UK，客户端可见 UUID |
| `user_id` | bigint | 实际用户 |
| `session_id` | varchar(128) | 平台会话 |
| `client_ip` | inet/varchar | 来源 IP |
| `data_source_id` | bigint | 目标数据源 |
| `database_name` | varchar(256) | 目标数据库 |
| `schema_name` | varchar(256) | 可空 |
| `statement_type` | varchar(32) | SELECT/EXPLAIN/REDIS_READ 等 |
| `raw_statement` | text | 按审计权限加密或受控明文 |
| `normalized_statement` | text | 去常量形式 |
| `statement_hash` | varchar(64) | SHA-256 |
| `fingerprint` | varchar(128) | 方言指纹 |
| `decision_id` | varchar(64) | 权限判定 ID |
| `credential_id` | bigint | 只记录凭据元 ID |
| `status` | varchar(24) | QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELED/TIMED_OUT/REJECTED/UNKNOWN |
| `submitted_at` | timestamptz | 提交时间 |
| `started_at` | timestamptz | 开始时间 |
| `finished_at` | timestamptz | 完成时间 |
| `duration_ms` | bigint | 执行总耗时 |
| `row_count` | bigint | 返回行数 |
| `result_bytes` | bigint | 返回字节数 |
| `truncated` | boolean | 是否截断 |
| `error_code` | varchar(64) | 平台标准错误码 |
| `error_summary` | varchar(1000) | 遮蔽后的错误摘要 |
| `trace_id` | varchar(64) | 链路追踪 |

该表按 `submitted_at` 月分区。索引至少包括：用户时间、数据源时间、指纹时间、状态时间。

### 5.4 `dbg_query_resource`

`execution_id`、`resource_id`、`access_type`、`column_set_hash`，用于记录 SQL 涉及的全部资源。

### 5.5 `dbg_query_policy_hit`

记录 `execution_id`、`decision_id`、`grant_id`、`rule_code`、效果、限制快照。拒绝查询也应产生记录。

### 5.6 `dbg_export_job`

保存导出申请、查询指纹、资源快照、限制、状态、行数、字节数、对象存储 Key、文件哈希、加密信息引用、下载次数、过期时间和删除时间。不保存可公开访问 URL。

### 5.7 `dbg_change_order` 与 `dbg_change_execution`

`dbg_change_order` 保存不可变 SQL/Redis 变更快照、目标、预检查、影响估算、回滚方案、流程实例和执行窗口。  
`dbg_change_execution` 保存每次尝试、执行节点、凭据 ID、开始/结束、状态、影响行数和遮蔽错误。禁止失败后自动重放非幂等变更。

## 7. 慢查询

### 7.1 `dbg_slow_source`

保存数据源、采集类型（MYSQL_SLOW_LOG、MYSQL_PERF_SCHEMA、ALIYUN_API、PG_STAT_STATEMENTS、PG_LOG、REDIS_SLOWLOG）、采集间隔、状态和监控凭据引用。

### 7.2 `dbg_slow_cursor`

保存来源 ID、分区键、游标 JSON、最后记录时间、最近成功时间、连续失败次数和版本。游标更新使用乐观锁。

### 7.3 `dbg_slow_fingerprint`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint | PK |
| `data_source_id` | bigint | 索引 |
| `database_name` | varchar(256) | 可空 |
| `engine` | varchar(32) | 类型 |
| `fingerprint` | varchar(128) | 指纹 |
| `normalized_statement` | text | 归一化语句 |
| `first_seen_at` | timestamptz | 首次 |
| `last_seen_at` | timestamptz | 最近 |
| `risk_flags` | jsonb | 全表扫描等标记 |
| `governance_status` | varchar(24) | 治理状态 |
| `assignee_id` | bigint | 负责人 |

唯一索引：`data_source_id + database_name + engine + fingerprint`。

### 7.4 `dbg_slow_sample`

保存来源唯一键、指纹 ID、开始时间、耗时、锁等待、扫描行、返回行、客户端、数据库用户、脱敏样例、原始值访问级别和采集时间。按发生日期日/月分区；高容量下保留有限样例，其余仅聚合。

### 7.5 `dbg_slow_bucket`

按 5 分钟和 1 小时窗口保存指纹 ID、次数、总/平均/最大/P95 耗时、扫描行、返回行、错误数和来源完整性标志。唯一键为 `fingerprint_id + granularity + bucket_start`。

### 7.6 `dbg_slow_governance_log`

记录指纹状态变化、负责人变化、评论、优化说明、验证窗口和前后指标，全部追加写入。

## 8. 告警和通知

### 8.1 `dbg_alert_rule`

保存名称、作用范围、指标、操作符、阈值、持续时间、首次出现条件、严重级别、去重窗口、静默配置、路由和状态。复杂条件使用受版本控制的 JSON DSL。

### 8.2 `dbg_alert_event`

保存规则、去重键、资源、指纹、状态（PENDING/FIRING/ACKNOWLEDGED/RESOLVED/SILENCED）、首次/最近触发、计数、当前值、恢复时间和负责人。

唯一活动事件约束通过应用锁或部分唯一索引实现：同一 `dedup_key` 同时最多一个未解决事件。

### 8.3 `dbg_notification_channel`

保存类型、名称、非秘密配置、秘密引用、状态和最近验证时间。Webhook Secret、SMTP 密码不得直接放入 `config`。

### 8.4 `dbg_notification_delivery`

保存事件、通道、模板版本、目标摘要、状态、尝试次数、下次重试、HTTP/SMTP 响应摘要、创建和完成时间。消息正文只保留脱敏后的渲染版本或哈希。

## 9. 数据保留和分区

| 数据 | 在线保留 | 归档/销毁 |
|---|---|---|
| 查询执行 | 12 个月 | 月分区归档后删除 |
| 权限/审批/导出/变更审计 | 36 个月 | 归档并校验后删除 |
| 登录/普通管理审计 | 12 个月 | 归档后删除 |
| 慢查询样例 | 默认 30 天 | 只保留聚合；可配置 |
| 5 分钟聚合 | 180 天 | 合并为小时聚合 |
| 小时聚合 | 24 个月 | 合并为天聚合 |
| 天聚合 | 36 个月 | 到期删除或归档 |
| 导出文件 | 默认 24 小时，最长 7 天 | 自动删除并记录 |
| 收藏 SQL | 用户删除或离职回收 | 删除前安全审计 |

清理流程必须先生成归档清单、记录数和哈希，验证成功后才删除在线分区。

## 10. 数据库迁移规范

- 使用上游项目现行数据库脚本/迁移方式；如未统一迁移工具，项目必须在首个迭代确定并固定。
- 每次迁移包含前向脚本、必要的回滚说明和数据影响评估。
- 不直接修改已在生产执行的迁移脚本。
- 新索引在大表上使用 PostgreSQL 支持的低锁方式并在运维窗口执行。
- 分区创建任务提前至少一个月创建未来分区。
- 所有枚举在代码与数据库约束/字典中保持一致。
