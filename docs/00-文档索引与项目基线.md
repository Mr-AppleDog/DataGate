## 3. 已确认的产品决定

### 3.1 使用对象

- 公司内部单组织平台，不对外提供多租户 SaaS。
- 所有正式员工均可拥有平台账号，但默认没有任何数据源访问权限。
- 组织、部门、岗位、人员、菜单和后台功能权限复用 RuoYi-Vue-Plus。
- RuoYi-Vue-Plus 自带多租户能力在本项目中关闭或固定为系统租户；前端不展示租户管理菜单。

### 3.2 登录与账号

- 首版只提供本地账号登录，不开放公开注册。
- 管理员创建账号；首次登录强制改密。
- 支持密码复杂度、失败锁定、会话超时、强制下线、禁用立即失效。
- 正式上线必须支持 TOTP 双因素认证。
- 保留 LDAP、OIDC、钉钉等统一身份扩展点，但不属于 MVP。
- 保留一个受严格管控的本地应急管理员账号。

### 3.3 数据源范围

第一阶段必须支持：

- MySQL、自建 MySQL、阿里云 RDS MySQL、PolarDB MySQL。
- PostgreSQL、自建 PostgreSQL、阿里云 RDS PostgreSQL。
- Redis、阿里云 Tair。

第二阶段候选：MongoDB、ClickHouse、SQL Server、Oracle、Elasticsearch/OpenSearch。

平台采用数据源插件和能力声明设计。不得把所有数据源假设为 SQL、数据库、Schema、表四级结构。

### 3.4 操作边界

- 普通用户在生产环境只允许安全读取和执行计划分析。
- 数据导出使用独立动作权限并经过审批。
- DML、DDL 必须经过审批并使用专用变更账号执行。
- Redis 普通用户只允许安全读命令；高风险命令默认拒绝。
- DBA 也不绕过审计；高危操作需要二次确认或审批。

### 3.5 权限边界

- 关系型数据库首版支持实例、数据库、Schema、表级权限。
- Redis 首版支持实例、逻辑 DB、Key 前缀、命令类别权限。
- 字段级权限和动态脱敏属于正式上线范围。
- 通用行级权限不实现；确有需要时通过数据库视图或专用数据服务解决。
- 无授权默认拒绝；显式拒绝优先；细粒度规则优先于粗粒度规则。

### 3.6 凭据托管

- 每个数据源至少区分查询账号、变更账号和监控账号。
- 密码使用 AES-256-GCM 加密；主密钥不保存于业务数据库。
- 主密钥通过 Docker/Kubernetes Secret 或只读文件挂载提供。
- 密码不回显、不下载、不写日志；编辑时只能覆盖。
- 首版人工轮换；后续实现自动轮换。
- 允许平台使用共享的专用数据库账号，人员归因由平台审计保证。

### 3.7 审批

- 查询权限：资源 Owner 或 DBA 单级审批。
- 导出：资源 Owner + DBA 两级审批。
- DML/DDL：业务负责人 + DBA 两级审批。
- 紧急权限：双人审批，最长 2 小时，自动回收。
- 申请人与审批人不得为同一人。
- 审批流按环境、数据源和操作类型配置，基于 WarmFlow 实现。

### 3.8 审计

- 查询和管理审计保存 1 年。
- 权限、导出、DDL、DML 审计保存 3 年。
- 保存完整 SQL 和执行元数据，不保存查询结果。
- SQL 中的密码、Token 和敏感常量在进入普通日志前必须遮蔽。
- 审计记录不可通过普通业务接口修改或删除。
- 支持归档、审计报告和哈希链防篡改校验。

### 3.9 慢查询与告警

- MySQL：Slow Log、Performance Schema、阿里云慢日志 API。
- PostgreSQL：`pg_stat_statements` 和数据库日志。
- Redis/Tair：`SLOWLOG GET`。
- 默认每分钟采集，目标在 5 分钟内形成告警。
- 支持钉钉、邮件和通用 Webhook；飞书、企业微信作为同一通知 SPI 的扩展。
- 治理状态：发现、已认领、处理中、待验证、已解决、已忽略。

### 3.10 部署和容量

- 试用部署：单机 Docker Compose。
- 生产部署：两个应用节点、负载均衡、独立元数据库、独立 Redis。
- 仅允许办公网、公司内网或 VPN 访问。
- 数据库安全组只允许平台执行节点和采集节点访问。
- 平台故障不影响业务应用直连数据库。
- RPO 15 分钟，RTO 1 小时。
- 容量基线：1,000 名用户、300 个数据源、100 人同时在线、50 个并发查询、每天 100 万条慢查询原始记录。

## 4. 技术基线

### 4.1 上游版本

- 后端固定使用 [`dromara/RuoYi-Vue-Plus` v5.6.2](https://github.com/dromara/RuoYi-Vue-Plus/releases/tag/v5.6.2)，发布 commit 为 `8136a01`。
- 前端固定使用 [`CrazyLionCat/plus-ui` v5.6.2-v2.6.2](https://github.com/CrazyLionCat/plus-ui/releases/tag/v5.6.2-v2.6.2)，发布 commit 为 `d0d4519`。
- 不直接从移动的 `5.X` 或前端主分支构建生产版本。
- 上游升级只能通过独立升级任务，在完成差异审查、迁移和回归测试后合并。
- 保留上游 MIT `LICENSE` 和版权信息。
- v5.6.2 的工作流任务改派接口存在一份公开的对象级授权缺失报告。实施前必须核对精确源码；若接口仍缺少菜单权限和任务归属校验，先禁用或修复并完成低权限劫持回归测试，不能因 GitHub Issue 已关闭就推断风险已消失。参考：[RuoYi-Vue-Plus Issue #44](https://github.com/dromara/RuoYi-Vue-Plus/issues/44)。

### 4.2 免费组件与许可证基线

- 平台会话、缓存和分布式锁默认部署 Valkey，采用 BSD-3-Clause，降低内部平台采用强 Copyleft 或 Source Available 条款带来的合规评估成本；通过 Redisson/Redis 协议接入前必须完成兼容测试。
- 公司已有 Redis 服务也可复用，但必须锁定具体版本和许可证。Redis 7.2 及以前为 BSD-3-Clause；7.4 至 7.8 为 RSALv2/SSPLv1；Redis 8 起可选择 RSALv2、SSPLv1 或 AGPLv3，不能笼统写成“任意 Redis 版本均为 BSD”。
- 目标数据源继续支持 Redis 和阿里云 Tair；连接外部目标数据源不等于把其服务端软件打包进本平台。
- 依赖清单、镜像和驱动均需在 CI 生成 SBOM 并做许可证检查；发现 GPL/AGPL/SSPL/RSAL 或商业条款时必须由公司法务/开源合规负责人确认。

参考：[Redis 官方许可证矩阵](https://redis.io/legal/licenses/)、[Valkey 官方仓库许可证说明](https://github.com/valkey-io/valkey)。

### 4.3 复用与隔离原则

可直接复用：

- `ruoyi-system`：用户、部门、岗位、角色、菜单、本地账号、登录日志和在线用户。
- `ruoyi-workflow`：WarmFlow 审批流程。
- `ruoyi-job`：SnailJob 定时任务和重试任务。
- `ruoyi-common`：Sa-Token、Redisson、加密、校验、SpringDoc 等公共能力。

必须独立实现：

- 外部数据源资源模型和访问权限，不使用框架内部数据权限代替。
- 查询执行网关，不将用户管理的数据源直接注册为平台 ORM 数据源。
- 查询审计，不使用框架操作日志或 p6spy 代替。
- 任意结果集的字段级脱敏，不只依赖 DTO 序列化脱敏注解。
- 慢查询采集、指纹、聚合、治理和告警。

## 7. 冲突处理

若文档之间存在冲突，按以下顺序处理：

1. 本文“已确认的产品决定”。
2. 对应专项设计文档。
3. 产品需求规格说明书。
4. 代码中的既有行为。

不得以“框架原本如此”为理由覆盖本项目安全要求。发现无法同时满足的冲突时，必须停止相关实现并形成决策记录。
