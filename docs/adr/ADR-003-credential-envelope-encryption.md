# ADR-003 为什么凭据采用信封加密且 KEK 外置

- 状态：已确认（2026-08-26，M0）
- 背景：平台集中托管数据库查询/变更/监控账号密码；威胁模型要求元数据库泄露时不泄露任何目标库口令（docs/08）。

## 决策

- 数据密钥（DEK）：每个凭据版本使用 AES-256-GCM 加密，密文/Nonce/算法/密钥版本存 `dbg_credential_version`（bytea）；
- 密钥加密密钥（KEK）：不存业务数据库，经 Docker/K8s Secret 或只读文件挂载注入（KEK Provider SPI）；
- 凭据只写不可读回：无任何查看/下载密码的 API；编辑=覆盖式新建版本；轮换产生新版本，旧版本 RETIRED。

## 理由

- 信封加密使 KEK 轮换不需要重加密全部密文；
- KEK 外置保证「元数据库 + 备份泄露」不等于「全部生产库口令泄露」；
- GCM 提供密文完整性，替换 credentialId 的密文无法通过认证（M1-02 验收项）。

## 影响

- `SecretValue` 值对象 toString 永久掩码；秘密不进入日志/异常 message/缓存/审计；
- 应用启动时 KEK 缺失必须失败关闭；
- KEK 恢复纳入 M6 备份恢复演练（RPO/RTO 门禁）。
