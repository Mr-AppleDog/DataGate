# ADR-004 为什么 SQL 必须 AST 解析并失败关闭

- 状态：已确认（2026-08-26，M0）
- 背景：受控执行的前提是准确知道语句类型与引用资源集合；正则/关键字无法可靠处理方言、引号、注释、子查询、函数与混淆写法。

## 决策

- P0 使用 Alibaba Druid SQL Parser（仅 Parser/AST/Visitor，Apache-2.0，版本锁定 1.2.28）；
- 解析失败、未知语法、超出白名单的语句一律拒绝（失败关闭），不得交给数据库试运行；
- 授权基于 AST 提取的规范化资源集合，WallFilter 不作为最终授权依据；
- 攻击语料（docs/06、08）版本化管理，解析器/驱动/连接器升级必须全量回归。

## 理由

- 资源级授权的正确性依赖完整的引用资源集合；漏识别一张表即越权；
- 「先执行再看报错」会把未授权写入送到目标库，违反零副作用要求；
- 方言 AST 提供 MySQL/PostgreSQL 各自的 Lexer，避免跨方言歧义。

## 影响

- 解析器升级 = 安全敏感变更，需跑安全语料回归（拒绝的请求确认未到达目标库）；
- Druid 连接池与 WallFilter 不进入执行链路；目标库连接池使用 HikariCP（ADR-005）。
