# ADR-005 为什么执行器先与应用同制品、按角色隔离，何时物理拆分

- 状态：已确认（2026-08-26，M0）
- 背景：执行器（ruoyi-db-executor）直连受管数据源，资源消耗与安全要求高于普通 Web 请求；但 M0-M3 容量有限（50 并发查询）。

## 决策

首版执行器与平台同制品部署（ruoyi-admin 统一装配），但在进程内强隔离：

- 按数据源 × 凭据用途建立独立 HikariCP 小池（默认最大 5 连接），不注册进 dynamic-datasource；
- 执行器只接受服务端构造的 ExecutionPlan，拒绝「数据源 ID + 任意 SQL」；
- 平台级/数据源级/用户级并发许可分离。

## 物理拆分触发条件（满足任一即评估）

- 持续并发查询 > 100；
- 应用节点因驱动或结果集内存压力频繁重启；
- 执行节点需要部署到多个网络区域；
- 执行节点需要更严格的主机权限与密钥访问策略。

## 影响

- executor 的公开接口不得依赖 Web Controller、RuoYi Mapper 或页面 DTO，保证可拆分；
- 凭据轮换使旧连接池停止借出并在归还后关闭；
- 查询取消跨节点经 Redis 注册表路由（docs/05 第 2.5 节）。
