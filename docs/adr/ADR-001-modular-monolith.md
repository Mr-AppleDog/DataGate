# ADR-001 为什么选择模块化单体（modular monolith）

- 状态：已确认（2026-08-26，M0）
- 背景：DataGate 需要身份、凭据、授权、执行、审计、慢查询、告警等多个边界清晰的模块；团队规模小（可单人/AI 维护），容量基线 1000 用户/300 数据源/50 并发查询。

## 决策

采用模块化单体：所有 `ruoyi-db-*` 模块由 `ruoyi-admin` 装配为一个部署单元；模块间只能通过公开 Service/SPI 或领域事件调用，禁止跨模块直接注入 Mapper。

## 理由

- 该容量规模下微服务只增加运维成本（多制品、多流水线、分布式事务、链路治理），不带来对应收益；
- 单体便于保证「解析→授权→执行→审计」链路的强一致事务边界（如审计失败关闭）；
- 模块边界 + SPI 约束保留了未来拆分执行器的路径（见 ADR-005）。

## 影响

- 模块边界靠包结构与依赖方向约束：core 无持久化依赖；connectors 只依赖 core；业务模块不经 Mapper 互调；
- 应用节点无状态，可水平扩到 2+ 节点（docs/02 第 1 节）。
