# 产品需求规格说明书

## 1. 产品概述

### 1.1 产品定义

数据库访问治理平台是公司内部统一的数据源访问入口。平台集中托管数据库专用账号，员工使用个人平台账号登录，根据资源权限在线查询或申请受控操作；平台记录实际操作人并采集业务产生的慢查询，形成发现、通知、认领、处理和验证闭环。

### 1.2 产品目标

1. 普通员工不再获得生产数据库账号和密码。
2. 统一表达“谁、在什么时间、可以对哪个数据源的哪个资源、执行什么动作”。
3. 生产查询、导出和变更全部通过受控入口完成。
4. 查询执行具备语法解析、权限校验、超时、限行、并发控制和审计。
5. 支持 MySQL、PostgreSQL、Redis/Tair 三类数据源的统一资产和差异化操作。
6. 采集平台外应用产生的慢查询，并完成告警和治理闭环。
7. 在 1,000 名用户、300 个数据源规模下稳定运行并支持横向扩展。

### 1.3 成功指标

上线 3 个月后的目标：

- 100% 生产数据源禁止开发人员使用共享密码直连。
- 100% 平台查询可关联实际员工、授权来源和目标资源。
- 100% 权限到期自动回收。
- 99% 慢查询数据在 5 分钟内完成采集；采集失败有平台告警。
- 95% 告警在 1 分钟内完成通知投递。
- 不发生因平台越权、解析绕过或凭据泄露导致的生产安全事件。
- 平台查询超时或故障不影响业务应用数据库连接。

## 2. 范围

### 2.1 P0：MVP 上线范围

- 本地账号、用户、部门、岗位、角色、菜单和 TOTP。
- 数据源录入、连接测试、环境标签、Owner、元数据同步。
- 查询、变更、监控三类凭据的加密托管和人工轮换。
- MySQL、PostgreSQL、Redis/Tair 数据源适配。
- 关系库实例/数据库/Schema/表授权；Redis 实例/逻辑 DB/Key 前缀/命令类别授权。
- 权限申请、审批、临时授权和自动回收。
- MySQL/PostgreSQL SQL 工作台和 Redis 安全工作台。
- 生产只读查询、执行计划、超时、行数、字节数和并发限制。
- 查询审计、登录审计、权限审计和管理审计。
- 慢查询采集、指纹聚合、趋势、基础告警和通知。
- 单机试用部署和双节点生产部署说明。

### 2.2 P1：全员推广范围

- 字段级权限、动态脱敏和临时明文豁免。
- 受控数据导出和审批。
- DML/DDL 工单、预检查、审批和专用账号执行。
- 审计归档、报告和防篡改校验。
- 慢查询负责人、治理状态、EXPLAIN 和优化前后验证。

### 2.3 P2：后续增强

- LDAP/OIDC/钉钉身份提供者实际接入。
- 飞书、企业微信通知通道。
- MongoDB、ClickHouse、SQL Server、Oracle、Elasticsearch/OpenSearch。
- 自动索引建议、自动 SQL 改写、自动限流。
- 全量 SQL 洞察和长期检索。
- SQL 客户端代理接入。
- 通用行级权限和跨数据源查询。
- 多组织、多租户 SaaS。

### 2.4 明确不做

- 不成为业务数据库的网络代理或必经链路。
- 不保存查询结果作为数据副本。
- 不允许普通管理员读取数据库密码。
- 不以正则表达式作为 SQL 安全判断的唯一依据。
- 不允许 DBA 使用隐藏的“超级模式”绕过审计。
- 不支持未经解析和权限定位的 SQL 在生产执行。

## 3. 用户和职责

| 角色 | 核心职责 | 默认数据权限 |
|---|---|---|
| 系统管理员 | 平台配置、账号、菜单、运行维护 | 无 |
| 安全管理员 | 密码策略、TOTP、审计策略、风险规则 | 无 |
| DBA | 数据源、凭据、查询策略、变更执行、慢查询治理 | 不自动拥有；需显式授权 |
| 资源 Owner | 负责指定数据源或数据库，审批查询和导出 | 可查看资源配置，不自动读取数据 |
| 业务负责人 | 审批 DML/DDL 的业务影响 | 无 |
| 开发人员 | 查询授权数据，申请导出或变更 | 默认无 |
| 运维人员 | 查看实例状态、采集器、慢查询和告警 | 默认无业务数据读取权 |
| 审计员 | 查看和导出审计记录 | 不可执行查询 |
| 应急审批人 | 审批紧急短期访问 | 不自动拥有访问权 |

职责分离要求：

- 系统管理员、审计员、审批人不会因后台角色自动获得业务数据权限。
- 申请人不能审批自己的申请。
- 凭据管理员不能直接查看密文对应的明文。
- 审计记录的归档和销毁必须由独立任务执行。

## 6. 关键业务流程

### 6.1 查询流程

```text
选择数据源与数据库
→ 编辑 SQL
→ 方言解析和资源提取
→ 功能权限校验
→ 数据资源权限校验
→ 安全规则和额度校验
→ 选择专用查询账号
→ 执行并流式限制结果
→ 动态脱敏
→ 返回结果
→ 写入查询审计
```

任何一步失败均不进入下一步，并记录拒绝或失败审计。

### 6.2 权限申请流程

```text
填写资源、动作、用途和有效期
→ 系统检查是否已有有效权限
→ 计算审批模板
→ Owner/DBA 审批
→ 创建授权快照
→ 缓存失效通知
→ 到期任务自动回收
```

### 6.3 导出流程

```text
基于已验证的 SELECT 创建导出申请
→ Owner 审批
→ DBA 审批
→ 独立队列重跑 SQL
→ 行数/字节数/脱敏限制
→ 生成加密水印文件
→ 有效期内限次下载
→ 到期删除文件
```

### 6.4 慢查询治理流程

```text
增量采集
→ 去重与指纹聚合
→ 规则计算
→ 告警去重和路由
→ 通知
→ 负责人认领
→ 优化处理
→ 观察窗口验证
→ 解决或回退处理中
```

## 7. 非功能需求

### 7.1 性能和容量

- 支持 1,000 名用户、300 个数据源、100 人同时在线。
- 平台交互查询总并发默认 50，可配置；单用户默认 3。
- 权限判断在缓存命中时 P95 小于 50ms，未命中时 P95 小于 200ms。
- 查询进入数据库前的平台额外处理 P95 小于 300ms，不含数据库执行时间。
- 慢查询日采集 100 万条，原始记录按天分区或等价分片。
- 普通列表接口 P95 小于 500ms，审计大范围检索 P95 小于 3 秒。

### 7.2 可用性

- 生产应用服务至少两个实例，无本地会话依赖。
- 单应用节点故障后 5 分钟内恢复对外服务。
- 平台不可用不影响业务应用连接数据库。
- 正在运行的查询不会自动重放；状态无法确认时标记 `UNKNOWN` 并告警。

### 7.3 数据一致性

- 授权创建、审批完成和缓存失效必须有可靠事件或补偿任务。
- 凭据轮换采用“验证新凭据—切换版本—旧连接自然回收”的顺序。
- 审计核心记录与操作提交至少保证同进程同步落库；扩展归档允许异步。
- 慢查询采集使用来源唯一键和游标保证幂等。

### 7.4 可维护性

- 数据源差异通过 Connector SPI 隔离。
- 每个模块拥有清晰 API，不跨模块直接访问 Mapper。
- 所有安全规则、权限判定和 SQL 解析必须有自动化测试。
- 上游 RuoYi 更新与业务模块变更分开提交和审查。

### 7.5 可观测性

- 暴露登录失败、权限拒绝、查询并发、超时、连接池、采集延迟、告警投递等指标。
- 日志使用结构化 JSON，包含 traceId，但不包含秘密和查询结果。
- 核心链路具备指标、日志和审计三种可观测信息。

## 8. 页面级验收原则

- 页面隐藏不构成权限控制，所有操作必须由服务端重新鉴权。
- 列表只返回用户可发现的资源。
- 无权和资源不存在对普通用户使用统一响应，避免枚举资源。
- 所有长任务显示进度、状态、失败原因和重试信息。
- 查询结果、SQL 样例和下载文件明确标记脱敏状态。
- 危险操作显示目标资源、影响范围和审批依据，不能只提供一个确认按钮。

## 9. 上线门槛

以下任一条件未满足不得全员上线：

- 生产数据源查询账号不是只读账号。
- 数据库密码可通过页面、接口、日志或异常获取。
- SQL 或 Redis 命令存在已知权限绕过。
- 查询超时不能取消，或连接泄漏压测不通过。
- 查询、授权、导出或变更缺少实际人员审计。
- 审批人可以审批自己的申请。
- 慢查询采集失败没有监控和告警。
- 备份未经过恢复演练。
