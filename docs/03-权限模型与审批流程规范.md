# 权限模型与审批流程规范

## 1. 设计原则

1. 默认拒绝：没有明确有效的允许授权即拒绝。
2. 双层授权：RuoYi 功能权限和外部数据资源权限必须同时通过。
3. 显式拒绝优先：任一有效拒绝规则可阻止操作。
4. 最小权限：查询、导出、明文、DML、DDL、Redis 写入彼此独立。
5. 有限时效：生产权限必须具有有效期；长期权限也需要定期复核。
6. 可解释：每次判定返回决策 ID、授权来源、命中拒绝和限制条件。
7. 职责分离：管理平台、审批和访问数据不是同一类权限。
8. 服务端强制：页面菜单和按钮不构成安全边界。

## 2. 两层权限

### 2.1 功能权限

由 RuoYi 菜单、按钮和 Sa-Token 权限控制，例如：

- `db:resource:list`
- `db:resource:add`
- `db:auth:grant`
- `db:query:execute`
- `db:export:apply`
- `db:change:apply`
- `db:audit:read`
- `db:slow:read`
- `db:alert:manage`

功能权限只说明用户是否能使用某项平台功能，不说明能访问哪个数据库。

### 2.2 数据资源权限

由 `ruoyi-db-auth` 控制。一个授权由以下部分组成：

```text
Grant = Effect + Subject + Resource + ActionSet + Conditions + Validity + Source
```

| 字段 | 含义 |
|---|---|
| Effect | `ALLOW` 或 `DENY` |
| Subject | 用户、部门或用户组 |
| Resource | 规范化资源 ID |
| ActionSet | 一个或多个资源动作 |
| Conditions | IP、时间、行数、超时、脱敏级别等 |
| Validity | 开始时间、结束时间、状态 |
| Source | 人工授权、审批工单、系统策略、紧急授权 |

## 3. 资源模型

### 3.1 通用字段

所有资源保存在统一目录中：

- `resource_id`：平台内部不可变 ID。
- `data_source_id`：所属数据源。
- `parent_id`：父资源。
- `resource_type`：类型枚举。
- `physical_name`：数据源中的真实名称。
- `display_name`：平台显示名称。
- `canonical_path`：审计和可读展示使用的规范路径。
- `status`：ACTIVE、DISABLED、DROPPED、UNKNOWN。
- `metadata_version`：元数据版本。

授权始终引用 `resource_id`，不得仅引用可变名称。

### 3.2 MySQL

```text
DATA_SOURCE
└─ DATABASE
   └─ TABLE / VIEW
      └─ COLUMN
```

### 3.3 PostgreSQL

```text
DATA_SOURCE
└─ DATABASE
   └─ SCHEMA
      └─ TABLE / VIEW / MATERIALIZED_VIEW
         └─ COLUMN
```

系统 Schema 默认不可见；允许列表由安全配置决定。

### 3.4 Redis/Tair

```text
DATA_SOURCE
└─ LOGICAL_DATABASE
   └─ KEY_PREFIX_POLICY
```

Redis Key 不全部同步为资源。Key 前缀策略示例：

- `order:*`
- `session:service-a:*`
- 精确 Key `feature:global-switch`

模式仅支持受控 glob 子集；禁止任意正则导致性能和语义不确定。

## 4. 动作模型

### 4.1 通用动作

| 动作 | 说明 |
|---|---|
| `DISCOVER` | 在目录和搜索中看到资源 |
| `METADATA_READ` | 查看字段、索引、类型等元数据 |
| `OWNER_MANAGE` | 维护 Owner，不包含数据读取 |
| `SLOW_READ` | 查看该资源的慢查询聚合 |
| `SLOW_SAMPLE_READ` | 查看慢查询样例，默认参数脱敏 |

### 4.2 关系型动作

| 动作 | 说明 |
|---|---|
| `QUERY` | 执行允许的只读查询 |
| `EXPLAIN` | 获取执行计划 |
| `EXPORT` | 创建并下载受控导出 |
| `COLUMN_UNMASK` | 查看指定敏感列明文 |
| `CHANGE_DML` | 经工单执行 DML |
| `CHANGE_DDL` | 经工单执行 DDL |

### 4.3 Redis 动作

| 动作 | 说明 |
|---|---|
| `REDIS_SCAN` | 按授权前缀浏览 Key |
| `REDIS_READ` | 读取类型、TTL、长度和值 |
| `REDIS_WRITE` | 经工单写值、修改 TTL |
| `REDIS_DELETE` | 经工单删除 Key |
| `REDIS_ADMIN` | 极少数受控管理命令，仅 DBA 特殊工单 |

动作不自动包含其他动作。例如 `QUERY` 不包含 `EXPORT`，`REDIS_READ` 不包含 `REDIS_SCAN`。

## 5. 权限继承

### 5.1 资源继承

父资源授权默认向下继承，除非授权设置 `inherit=false`：

- MySQL 数据库 `QUERY` 可继承至其表。
- PostgreSQL Schema `QUERY` 可继承至其表。
- 数据源级 `DISCOVER` 可让用户看到数据源，但不自动具有 `QUERY`。
- Redis 逻辑 DB 的 `REDIS_READ` 不意味着可以读取所有 Key；生产必须至少指定 Key 前缀。

### 5.2 主体继承

用户有效授权来自：

- 用户直接授权。
- 所属部门及其上级部门授权，是否继承由授权配置决定。
- 用户组授权。
- 审批工单生成的临时授权。

岗位只用于功能角色分配，默认不直接授予数据资源权限，避免岗位变化意外扩大数据访问范围。

## 6. 条件模型

支持以下标准条件：

| 条件 | 示例 |
|---|---|
| `sourceIpCidr` | 只允许办公网或 VPN 网段 |
| `timeWindow` | 工作日 08:00-22:00 |
| `maxRows` | 最多返回 1,000 行 |
| `maxBytes` | 最多返回 10MB |
| `maxExecutionSeconds` | 最长执行 30 秒 |
| `maskingLevel` | 仅允许 `MASKED` |
| `requireMfa` | 必须完成 TOTP |
| `requireRecentReauth` | 5 分钟内二次认证 |

环境硬限制永远优先于授权条件。授权不能把生产硬上限扩大到系统允许值之外。

## 7. 判定算法

### 7.1 输入

- actorId、sessionId、sourceIp。
- featurePermission。
- resourceId、action。
- requestContext：查询类型、请求行数、执行时间、是否导出等。

### 7.2 步骤

```text
1. 校验用户、会话、TOTP 和账号状态。
2. 校验 RuoYi 功能权限。
3. 校验资源存在、启用且用户可发现。
4. 加载用户、部门、用户组在资源及祖先资源上的候选授权。
5. 过滤未开始、已过期、已撤销和主体不匹配的授权。
6. 若存在匹配动作和条件的 DENY，立即拒绝。
7. 独立评估每条 ALLOW；至少一条完整满足才允许。
8. 将所有满足的 ALLOW 约束与环境硬限制合并。
9. 对字段计算 COLUMN_UNMASK 和脱敏策略。
10. 返回 decisionId、允许/拒绝、理由、授权来源和最终限制。
```

### 7.3 限制合并

- 环境硬上限不可突破。
- 多条有效允许授权可提供不同路径，取能够支持本次请求的路径。
- 最终行数、字节数和超时不超过“所选授权路径限制”和“环境硬上限”的较小值。
- 若客户端请求未指定限制，使用环境默认值。
- 拒绝规则不参与取最大或最小，只要匹配即拒绝。

### 7.4 判定响应

```json
{
  "decisionId": "...",
  "allowed": true,
  "reasonCode": "ALLOW_BY_APPROVAL_GRANT",
  "grantIds": ["..."],
  "limits": {
    "maxRows": 500,
    "maxBytes": 10485760,
    "maxExecutionSeconds": 30,
    "maskingLevel": "MASKED"
  },
  "policyVersion": 42
}
```

此对象供内部使用；面向普通用户的响应不得泄露无权资源名称或其他人的授权详情。

## 8. 权限缓存

- 缓存键：`actorId + resourceId + action + contextHash + policyVersion`。
- 默认 TTL 5 分钟，但权限变更同时增加 `policyVersion` 并广播失效。
- 用户禁用、退出、临时权限回收必须立即删除会话级缓存。
- 禁止缓存包含数据库密码或完整 SQL 的判定输入。
- 执行器在真正执行前重新检查数据源状态、计划过期时间和授权版本。

## 9. 预置平台角色

| 角色 | 功能权限 | 数据权限 |
|---|---|---|
| `platform_admin` | 系统管理 | 无 |
| `security_admin` | 安全策略、账号安全 | 无 |
| `dba` | 数据源、规则、工单执行、慢查询治理 | 需显式授权 |
| `resource_owner` | 查看名下资源、审批 | 不自动读取数据 |
| `developer` | 工作台、申请、本人历史 | 默认无 |
| `operator` | 监控、采集器、告警 | 默认无数据读取权 |
| `auditor` | 审计只读和报告 | 无查询权 |
| `emergency_approver` | 紧急审批 | 无查询权 |

不得给 `platform_admin` 或 `dba` 编写隐藏的全资源允许分支。

## 10. 审批模板

### 10.1 查询权限

```text
申请人 → 资源 Owner 或 DBA → 自动创建 Grant
```

- 生产申请必须填写用途、关联事项和结束时间。
- 单次最长 30 天；长期需求需重新申请或定期复核。
- 测试环境最长 180 天。

### 10.2 导出权限

```text
申请人 → 资源 Owner → DBA → 生成一次性导出授权
```

- 授权绑定申请 SQL 的指纹、资源集合和导出限制。
- 默认只允许执行一次；不得转化为长期 `EXPORT` 权限。
- 下载链接和文件均有独立有效期。

### 10.3 DML/DDL

```text
申请人 → 业务负责人 → DBA → 等待执行窗口 → 专用账号执行
```

- 审批对象包括不可变 SQL 快照、目标资源、影响评估和执行窗口。
- SQL 修改后原审批失效，必须重新检查和审批。
- 申请人不能充当最终执行审批人。

### 10.4 紧急权限

```text
申请人 → 两名不同审批人 → 最长 2 小时临时授权
```

- 必须填写事件编号和紧急原因。
- 必须完成 TOTP 和 5 分钟内二次认证。
- 不允许续期，只能重新申请。
- 开通、每次使用、到期和提前回收均发送通知。
- 事后 24 小时内必须补充复盘记录。

## 11. 流程状态机

```text
DRAFT
  └─submit→ PENDING
PENDING
  ├─approve all→ APPROVED
  ├─reject→ REJECTED
  ├─cancel by applicant→ CANCELED
  └─timeout→ EXPIRED
APPROVED
  ├─grant created→ ACTIVE
  └─execution scheduled→ WAITING_EXECUTION
ACTIVE
  ├─validity elapsed→ EXPIRED
  ├─manual revoke→ REVOKED
  └─resource disabled→ SUSPENDED
```

状态变化必须使用乐观锁或等价并发控制。重复回调不得重复创建授权或执行变更。

## 12. 权限复核

- 每月生成生产长期权限复核任务。
- Owner 查看名下用户、资源、动作、来源和最近使用时间。
- 90 天未使用的生产权限进入待回收建议。
- 用户离职、部门变动或账号禁用触发即时复核/回收。
- 复核操作写入权限审计并更新授权版本。

## 13. 必测场景

1. 用户有数据库级允许，但表级显式拒绝：表查询拒绝。
2. 用户通过部门获得权限，退出部门：权限立即失效。
3. 用户有查询权但无导出权：查询成功，导出申请可创建但不能直接导出。
4. JOIN 中包含一个无权表：整条 SQL 拒绝。
5. PostgreSQL 未显式 Schema 的表解析到当前 `search_path` 后鉴权。
6. Redis 用户拥有 `order:*`，访问 `orders:*`：拒绝。
7. 临时权限到期时存在旧 ExecutionPlan：执行器拒绝。
8. DBA 无显式数据授权：不能查询数据。
9. 申请人尝试调用审批 API 审批本人申请：服务端拒绝。
10. 资源被标记下线：所有新操作拒绝，历史审计仍可检索。
