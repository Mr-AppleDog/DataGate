## 问题概述

未认证访问数据源列表时，服务通过响应体业务码 `401` 表示认证失败，但 HTTP 传输状态仍为 `200`。资源名称未泄露，失败关闭行为有效，但 HTTP 契约与项目规范不一致。

## 需求与影响

- 需求 / 验收来源：`docs/05-API错误码与状态机规范.md` 的 HTTP 401 认证失败语义；`RES-006`
- 严重程度：`S2 Medium`
- 用户 / 业务影响：标准 HTTP 客户端、API 网关、监控和安全策略可能把认证失败误判为成功请求
- 关联测试用例 / 缺陷：`ST-RES-006` / `DEF-001`

## 环境

- 构建版本 / Git 提交：`8e94aea`
- 环境类型：local
- API 调用方：未认证
- Edge 辅助验证：Microsoft Edge + Codex 扩展；已认证数据源筛选 UI 正常

## 最小复现步骤

1. 启动 DataGate。
2. 不携带认证信息，请求 `GET /db/datasource/list?name=<existing-name>&pageSize=10&pageNum=1`。
3. 检查 HTTP 状态和 JSON 响应体。

## 预期结果

- HTTP 状态为 `401`。
- 返回稳定的认证失败响应。
- 响应不包含受保护的数据源名称。

## 实际结果

- HTTP 状态为 `200`。
- JSON 响应体业务码为 `401`，消息为“认证失败，无法访问系统资源”。
- 响应未包含受保护的数据源名称。

## 复现概率

- `1/1`

## 已脱敏证据

- HTTP status: `200`
- Content-Type: `application/json`
- Application code: `401`
- Protected datasource name present: `false`
- 未保留凭据、Token、Cookie、内部地址或原始敏感日志

## 故障边界与源码候选

- 证据支持的最小故障边界：认证异常到 HTTP 响应状态的映射层
- 源码候选：`ruoyi-common/ruoyi-common-satoken/src/main/java/org/dromara/common/satoken/handler/SaTokenExceptionHandler.java` 的 `handleNotLoginException` 返回 `R.fail(401, ...)`，但未设置 HTTP response status
- 上述源码位置是待修复验证的候选，不作为未经验证的最终根因

## 临时解决方案

调用方目前只能同时检查 HTTP 状态和响应体业务码，不能仅依赖 HTTP 状态。
